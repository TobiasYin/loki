# 真机最新会话的屏幕能力排查

日期：2026-10-17。

## 原始问题

用户最新会话要求操作上屏应用并观察视频内容。会话中的屏幕观察、联网、屏幕控制和调试开关均开启，但真实请求的工具列表没有 `perception.app_info`、`perception.capture_screen`、`perception.ui_tree` 和点击工具。模型只能搜索和查询已安装应用，随后报告无法操作或截图。

当时 Android 的无障碍全局开关和 Thor 组件均已启用，但 `dumpsys accessibility` 中 Thor 处于 Binding，Bound 服务中没有 Thor；应用也没有实际的 `ThorAccessibilityService.instance`。这不是模型忽略已提供的截图工具，而是 Native 的可用性判断没有发布这些工具。

## 修复链

1. 无障碍健康恢复：不把 settings 已启用当成真正就绪；只在已经授权的 Shizuku shell 下，通过连接宽限、单飞恢复和退避持续等待真实服务回调。恢复只操作本应用组件，重加前重新合并其他服务列表。已开启但连接中的状态标为临时不可用，避免让模型误以为用户未授权。屏幕请求首次发布工具前可在后台短暂等待恢复，主线程及不需要屏幕能力的请求不等待。
2. Pi 工具批次快照：此前在每个 `tool_execution_end` 后刷新观察，会提前晋升 Native 的 pending 快照，导致同一模型回复后续工具仍持有旧编号而被误拒绝。现在在官方 Pi 调用的 `finishTurn` 注入观察，整批工具完成后才晋升；由 Pi 的 `turn_end` 刷新队列，下一模型请求立即获得新观察。没有取消真实目标、屏幕、权限或坐标校验。

3. Pi 工具集合同步：不在官方已构建请求投影之后更改工具集合，改为在初始化和整批工具完成时更新。仅因固定 `TARGET_CHANGED` 暂不可用的已启用工具保留声明，实际执行仍受 Native 实时授权与目标检查约束，避免变成无恢复指引的 `Tool not found`。真正缺少后台或权限的工具仍不发布。

4. 派发回执：Native Gateway 的 `not_submitted` 现在以独立固定字段 `submission=not_dispatched` 传到 Runtime；不再把“调用已到 Native”当作“可能已提交 Android 输入”。普通 observed、未知回执和已提交回执仍保持各自含义。拒绝后由 Pi 根据重新截图和组件树决定新动作，不直接重放。

5. 请求目录与执行准入分离：每次模型请求使用 Native 签发、绑定模型配置修订和权限代次的工具目录，按 Pi 当前真正声明的集合验证保存；后续实时可用性变化不能导致这个已构建请求的上下文保存失败。实际执行仍走实时 Native 准入与 Gateway。目录只保存在传输和诊断清单，不写入模型系统前缀。

6. 截图坐标的独立缺陷：同批截图和组件树可以产生不同观察编号。帧坐标现在分别验证原截图和当前授权观察仍具有兼容的目标、布局、可触区域、显示信息与角色，同时匹配 session/run，并在提交前复查。原帧不会借新观察延长有效期。本次真机拒绝使用的是 display_logical，不能将其归因于这处帧坐标缺陷。

恢复检查额外覆盖了 Android ICU 对正则右花括号的严格处理、Shizuku 连接回调生命周期和绑定超时，以及系统状态输出必需部分完整性。对于 Android 框架确实残留 orphan Binding 的情况，只读确认移除完成后才重新开启本组件；持续异常会明确提示需要重启本应用，不循环制造新绑定。排查期间在无活动任务时对本应用做完整重启，并处理本组件的残留绑定；保留全部对话与配置，没有重启设备。

原用户会话及 Pi entries 不作为测试样本重写。独立真机验收只在自建会话和 Input Lab 模拟设置页运行，并核对原会话、配置与其他无障碍服务保留。

## 目标变化误判的进一步根因

真机对比确认：观察缓存、有效期、屏幕角色、显示代次、旋转、尺寸、应用和可触区域均相同，去除 structure 计数后的窗口布局也完全相同，但 structure 计数递增，导致输入从可用列表中消失。Thor 状态栏的实时内容与 subtree 事件此前会走到结构变化分支。

现在只对精确命中 SYSTEM 事件窗口、且窗口 root package 与事件 package 双向确认为 SystemUI 的非结构事件做内容处理。真实窗口身份、几何、焦点、遮挡和结构事件仍严格检查，应用自身的滚动、subtree 变化仍会更新 interaction。修复后同一真机流程零拒绝通过。

## 验证

独立真实模型验收通过：自动断开/恢复本应用无障碍，读取应用信息 1 次、截图 1 次、组件树 2 次，成功点击 1 次并进入 preferences 页面。6 条模型 HTTP 回执均为 200，工具错误与未派发拒绝均为 0。接收端独立封存日志核对一次按下、一次松开、一次导航，未保存或修改设置。模型执行耗时 16.19 秒；完整仪器测试 25.34 秒。

原用户会话、Pi entries、配置和其他无障碍服务摘要均保持一致，测试清理错误为 0。安装最终 APK 后正常启动应用，确认真实无障碍 ServiceRecord 存在，本组件不在 Binding/Crashed 集合；聊天恢复到下屏，上屏恢复原应用。

回归验证：Runtime 384 项、device core 255 项、应用单测 220 项、Native bridge 48 项全部通过；真机 Android 解析测试 3 项通过，集成类型检查及 Android lint 通过。固定状态、构建摘要和接收端摘要见 `tests/screen-recovery-evidence/`。完整模型记录及原始系统输出不作为公开证据提交。

已知系统边界：Android 真正残留 orphan Binding/Crashed 时可能需要完整重启本应用。v21 保留本组件 enabled 状态以便系统重启清理识别本包，不再将其永久留在 disabled，也不把设置读回当成服务已连接。本次设备状态已恢复。
