# GPT6-Luna MODEL_OUTPUT_LIMIT 排查与修复

2026-10-17，OpenCode Go / `gpt-6-luna`。

## 已确认的问题

历史失败为 HTTP 200、正常 EOF，Runtime 以 `MODEL_OUTPUT_LIMIT / stopReason=length` 结束。保存配置中的 `maxOutput=2048`，`maxOutputText` 为空；旧版 `selectedProfile` 将所有官方模型的输出预算取 `min(全局 maxOutput 默认 2048, 模型目录输出容量)`。Luna 目录容量为 128000，但本轮 low effort 实际被旧隐式默认预算压到 2048。

Pi Responses 只在 `response.incomplete` 且 `incomplete_details.reason=max_output_tokens` 时映射为 `length`，并非将所有 incomplete 或网络失败都分类为输出超限。思考与正文共享输出预算，小预算能够在正文或工具参数完成前耗尽。

**证据边界：** 历史记录没有保存 provider usage、实际请求报文或响应正文，无法追溯那次输入/输出/思考 token 的精确分配，不能断言 2048 全部消耗在思考上。后来相同模型、低 effort 的合成工具选择对照在 2048 和 128000 两档均成功，未完整复现历史失败。确定的配置缺陷已修复，后续超限新增安全数值诊断。

## 修复内容

- 官方 provider 的输出上限留空时，采用当前模型目录容量，不再让旧隐式 2048 覆盖模型配置。无需更改用户保存的 Key 或旧偏好文件。
- 明确填写的输出上限仍是用户上限；切换容量更小的模型时按当前容量约束，不重写原值。清空设置恢复自动。自定义 provider 保留既有默认与显式预算行为。
- 设置保存和连接测试使用同一预算策略，移除原 16384 硬上限；官方上下文取目录容量，而非禁用的自定义输入框默认值。页面说明思考也占用输出预算。
- 自动预算优先容纳当前内容与完整有界历史，再在共享上下文容量中分配本轮输出。为 Pi 保留 4096 估算余量和至少 16 输出 tokens，仅当总输入超出实际容量时按原机制丢最旧完整轮。这避免 Grok/Kimi 等目录输出容量等于上下文容量时，最大输出预留挤占全部输入空间。
- 实际请求仍受模型容量和 SDK clamp 约束；不会为了提高上限清空 Pi session，也没有新增模型时间上限。
- 每轮持久化专用 `model_round` 数值事件：实际请求输出预算、provider 实际报告的输入/输出/思考 tokens、白名单停止原因。未报告的字段不伪造为零；不保存正文、响应 ID、headers 或原始错误体；正常计量不会显示为 UI 错误。
- 真正输出超限仍结束本轮并保留上下文，UI 提示可在当前会话继续。截断工具参数零原生执行；阻止 Pi 对截断工具调用自动进入下一模型轮。明确追问继续复用 Pi Agent 和原效果记录。
