实际连接在既有 ADB server 5041，serial `THOR_DEVICE`；默认 5037 没有列出设备，没有重启或占用其他 server。最终设备 APK 的 SHA-256 回读为 `4875a8d185dd0c1af54bdadd24dd932777500141a49e96846025a3ca5df51f4f`，与本轮固定安装产物一致。

模型复用设备里已有的 OpenCode Go Responses / `deepseek-v4.1-flash`，使用资料中支持的 low 思考强度，实际每轮上下文上限为 1,000,000。此轮使用已缓存/内置 Go 模型资料，没有刷新在线模型列表。

## 上下文与 Skill 证据

同一会话先记住随机口令，追问正确返回，Native context 事件确认复用 Pi Agent。另一条带新口令的长回答在收到正文后，从实际输入区点击停止；运行为 cancelled，再追问正确返回新口令。随后销毁并重建 Activity、WebView 和 Native host，在同一会话返回最初口令，此时是新 Pi Agent 从持久记录恢复。**不是杀死整个 Android 应用进程的测试**；失败后恢复的其他条件仍以先前隔离 AVD 回归为准。

导入的是被测 Agent 在上一轮自行研究、修订后导出的原始 `stardew-valley-guide`，3 个文件、hash `ae10191293e4dc6277d77ff2181c94140a4b69098f9de0fba74a62811d73ead0`。本轮没有在真机重复编写攻略。通过 `+` 的真实选择器挂载，新会话提问“2 级但已持有铱金竿和钓具能否装上”。Agent 自行读取正文和 `references/rainy-catfish.md`，回答可以装备，区分购买条件与持有后的使用条件。

实际出站请求复核：首个请求不含任何攻略文件全文，正文和钓鱼专题只在明确读取后进入后续请求，未读取的作物专题在全部请求中均不存在。另一个新会话继承 Skill 与 low 选择，历史为空。之前星露谷测试中的跨季鱼类、排除随机商店等答案错误没有因本轮装备题通过而消除；该 Skill 仍是准确性未全部验收通过的试验产物。

## 保留的失败和剩余边界

- 首次上下文套件选择了此设备模型资料未公布的 minimal，Native 正确拒绝，尚未发出模型请求；改用公布的 low 后完成。该失败没有算作模型或产品失败。
- 前两次 IME 检查把 44 CSS 像素的物理舍入值 43.9973 判失败，布局截图与边界本身正常。测试加入半像素舍入容差，保留原失败证据后重跑。
- 没有重新探测 120 Hz，之前“两屏实际仍 60 Hz”的限制保留。未完成完整 POC-11、瞬时系统栏、原生手柄注入、指定游戏与组合故障矩阵，也没有实际运行星露谷。
- 本轮没有重测火山云 ASR、Brave 搜索或在线模型列表刷新；语音模式及设置入口通过，不等同于这些云服务全部重验。真机拒绝安装仍未补测，已有 AVD 拒绝用例单独保留。
- 聊天正文仍以纯文本显示 Markdown 标记，富文本排版未在本轮实现；不能把布局检查称为全部 UI 完善。

## 复现与证据

入口为 `scripts/physical-resume.py`，只接受明确 serial/port，并验证型号和非 qemu。`--suite` 可选 `context`、`ime`、`receiver`、`install`、`readback`；输出目录必须新建。仅升级安装、添加测试会话，不重置产品；只临时移除本应用无障碍组件以完成 APK 替换，保留其他服务，并在结束后恢复。每次固定 APK、副本哈希与相关源文件哈希。完整请求和私有数据库备份仅在忽略的 `build/physical/resume-2026-10-16/` 中。

```sh
python3 scripts/physical-resume.py --serial THOR_DEVICE --adb-port 5041 \
  --suite context --output build/physical/new-context-attempt
```

`context` 用例要求先把本仓库导出 ZIP 写到 Native 临时 cache（运行器处理），已有同名 Skill 则只接受完全相同 hash，不会覆盖用户修改。`install` 仅允许复用已保存真实配置，并需要两个明确的真机 opt-in；模拟器旧入口继续拒绝真机。测试已移除普通模型等待上限，UI 未提交任务的故障判定与接收端 30 秒观察窗仍独立存在。

可公开的结果、对话、截图和原始报告哈希见 [真机续测证据](../tests/physical-resume-evidence/README.md)。本轮只修改验收代码与文档，生产 APK 与上一轮软件验收一致。
