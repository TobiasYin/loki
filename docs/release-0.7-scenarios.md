# 0.7：多步上屏演练、精简组件树与百分比亮度

本轮扩展 Input Lab 的独立本地合成场景，使模型需要进入页面、改变控件、滚动查找并核对真实值。原 LAB 的物理基线、判定和历史报告保持独立；场景验收不代表所有第三方游戏兼容。

## 场景与验收方法

| 场景 | 模型任务 | 接收端独立证据 |
|---|---|---|
| 设置 | 进入设备偏好，切换模式与夜间阅读，真实拖动音量滑块并保存 | 导航、控件最终值、DOWN/MOVE/UP、至少两次用户进度改变、保存文件 |
| 游戏 | 仅通过截图完成两关颜色/形状/编号目标，读取口令 | 每关实际命中目标、零误触、终局口令与模型回答一致 |
| 新闻 | 查找首屏外指定新闻，滚动到可见后打开详情并读码 | 列表实际位移、正确文章 ID、打开次数与详情码 |
| 长文 | 打开专栏，读开头码，实际滚到末尾再读末尾码 | 正文滚动、末尾进入可见 viewport、两处验证码 |

每项独立随机 seed、任务和 ProductHost 会话，使用保存的 OpenCode Go / `deepseek-v4.1-flash` 配置与正常 Native 授权。模型不设任务总时限；默认模型请求预算从 12 轮增加到 40 轮，支持多步滚动与核对，Native 设备调用仍独立限定 32 次。预算失败后可在原会话继续，不清空上下文。测试准备接口仅通过签名保护的 debug Provider 提供，不作为模型工具。模型收到自然语言任务，不收到 seed、隐藏答案或固定坐标。

场景独立记录 `scenario-reports/<attemptId>/events.jsonl` 和 `report.json`。封存后核对完整原始文件的长度、SHA-256、连续序号、testRunId / agentRunId / attemptId 关联及丢失数。接收端只证明界面状态，`agentAnswerVerified=false`；模型回答由外部测试另外核对。`systemInjectionProven=false`，不冒充输入来源认证。

## 上屏结构与操作

`perception.ui_tree` 输出精简语义树，去除没有语义的布局包装，保留文字、状态、动作、边界、父子和滚动容器关系。可查询关键词、过滤非可见节点、分页及按文本偏移继续读取。密码字段不会进入搜索或返回正文。预算与截断原因明确返回，分页不能装下必要上下文时会提示增大预算，避免循环。

应用已经向 Accessibility 暴露的离屏文字可以快速读取；虚拟列表尚未加载的内容仍需真实滚动后观察。Canvas 游戏使用截图。节点引用只绑定最近一次实际观察，新的观察、输入、页面变化或过期后不能继续复用。

普通应用窗口保留所有窗口结构、焦点、层级、边界和遮挡校验；只有窗口类型、root 包名和事件包名共同确认的 SystemUI 纯内容更新不再误使应用观察失效。应用自身内容更新仍使旧观察过期。可触摸区域取应用、窗口和显示的交集，并排除更高层窗口；无法证明单一矩形安全区域时拒绝输入，不能点击系统栏。

`input.scroll` 操作当前可见容器公开的滚动动作；`input.drag` 以一次完整、有界的 down→move→up 拖动滑块或滚动条。API 接受动作不等于页面已经移动，Agent 必须再次观察验证。该拖动工具不提供跨调用持有或长按激活拖放。完整参数与边界见 [语义界面工具](../tools/semantic-ui.md)。

有界触摸将正常等待回调与异常退出后的结果未知分开管理，pending token 同时绑定 Run 和 request，早回调、晚回调或旧回调不会留下幽灵持有或错误清除新操作；Gateway 继续串行执行并保留权限、坐标和目标校验。

系统提示补充多步观察和操作流程，内置 adb-operations Skill 按需读取 [屏幕导航手册](../app/src/main/assets/skills/adb-operations/references/screen-navigation.md)，正文不会提前全部塞入上下文。

## 亮度接口

`debug.thor_brightness` 的 `value`、`before`、`brightness` 和 `requested` 统一为 0–100 的整数百分比，`unit=percent`。上、下屏分别通过 `screen=upper|lower` 选择。小数、负数、大于 100 或读取时携带 value 均拒绝。白名单调整直接执行。

设备固件的 0–255 转换留在 Native 内部，按最接近整数换算；写入后仍按固件一单位的严格量化容差验证，不能用扩大百分比误差掩盖未生效。工具卡、自然语言说明和内置操作手册同步使用百分比。通用 Shell 的系统命令仍保持原生命令格式，诊断读取需按明确单位解释。旧报告中的历史 0–255 数值不重写。

## 长任务记录与界面效率

多轮新闻/长文测试暴露了本地保存故障：模型 HTTP 已正常 200/eof，累积的完整 turn 超过 64 KiB 后却被当成消息头拒绝，RPC 的错误未关联回原请求，随后等待 185 秒。现在大 `host.rpc.data` 使用最多 16 MiB 的 UTF-8 数据体，路由头仍限 64 KiB；body 不得覆盖连接、请求或操作字段，也不能与 inline data 混用。已识别请求的非法/超限错误立即关联回复，保留正常来源、连接和授权校验。失败任务的旧记录保留，不自动重放输入。

聊天中的工具过程采用两层按需渲染：整体折叠时不创建全部工具卡；展开整体后只创建摘要；展开某张卡后才解析该卡参数与结果。正在看的工具结果会随流更新，未知结果、失败和批准入口仍能直接看到。历史亮度没有百分比标记时不推测单位，避免把旧固件数值误显示为百分比。
