# 页面变化后继续任务

应用翻页、弹出新窗口或控件位置变化时，Agent 会保留当前任务和上下文，进入重新观察流程，再根据新的截图或界面信息继续。用户无需因为一次页面变化重新发送任务。界面使用普通的“页面已变化，正在重新观察”提示。

## 当前提示的清除与折叠状态

页面变化只使用当前恢复状态显示提醒，不再从最后一条历史 `TARGET_CHANGED` 诊断追加常驻提示。同一工具调用的拒绝结果与 Pi 诊断按调用编号去重；诊断延迟到达也不会重新激活已经解除的提醒。当前屏幕的应用信息、窗口、组件树或截图读取成功且结果未丢弃后，提醒清除，历史工具条目显示“已重新观察”。失败读取、丢弃结果、另一块屏幕的图片或单独提交 A 键均不能代替实际重新观察。

终态运行不再保留“正在重新观察”的动态页面提醒，历史仍可展开查看；明确的未知提交状态保留在对应工具详情中，成功重新观察或任务结束后不再追加常驻提醒。工具失败、命令拒绝和未知结果也只在对应工具条目及其按需展开的详情里显示，Pi 的 `TOOL_FAILED` 按调用编号归入同一条工具记录，不再追加到全局消息末尾。迟到的工具诊断不会改变该工具的时序位置或打断后续思考文本；仅剩诊断的分页历史也有可查看的工具条目。任务本身失败、模型输出上限和当前审批仍按运行状态显示。

运行中折叠栏显示“正在运行 · 已完成 N 项操作”，按工具调用去重，只计入成功的 observed/submitted 结果，不计思考、待执行、拒绝和未知结果。结束后继续显示保存的用时。

最新提示审计更新通过 104 项前端测试、223 项 App JVM 测试、Android 静态检查及三种窗口尺寸的浏览器交互检查，覆盖拒绝结果加重复诊断、A 键后成功截图、延迟诊断、终态折叠、完成数更新，以及工具失败后成功输出和重载历史时不再出现全局工具提示；不修改 Pi 执行或 Native 输入校验。新 APK 已构建；本轮验证时未检测到 Thor，尚未覆盖安装这次更新。

消息末尾的通用诊断出口已移除。只有实际失败的任务显示模型输出上限或响应失败说明，每个任务保留一条可读原因；完成或仍在执行的任务不从旧诊断追加模型失败提醒。未识别的内部诊断仍保留在事件历史中，不直接显示为全局错误码。

Native 的所有 `tool.prepare` 拒绝均保留为原工具回执，不再另写全局“操作被拒绝”；原错误码、工具执行限制和模型接收的结果不变，真正的存储故障仍触发全局故障处理。能力变更失败由对应开关的确认结果就地显示，Skill 导入失败由现有即时反馈显示，不再重复追加常驻错误。成功的页面操作会清除旧的页面操作错误；存储故障不受此清除影响。

输入焦点不匹配时，Native 仅把四条已核对的本地固定拒绝，在对应手柄／导航工具中投影为 `input_focus_mismatch`。Runtime 先完成停止、权限、会话与能力复验，才采用这个提示；工具原始正文仍丢弃。模型会被告知先观察窗口和焦点，必要时自行决定使用已有且获准的应用启动或选屏触摸恢复焦点，再重新观察。截图本身不会恢复输入焦点。没有自动切焦点、自动点击、改焦点锁或重放动作。该补充包含在 Runtime 251 项回归与统一新软件构建中；对应安装包的设备验收另行记录。

重新观察不等于重试旧动作。Agent 会丢弃旧位置、截图坐标和控件引用；依赖页面的点击、拖动和应用启动，必须等当前屏幕的新观察通过校验后才能继续。切换屏幕、读取另一块屏幕的只读图片，都不能代替当前目标屏幕的观察。亮度、风扇、释放输入和必要的聊天退后台操作，不会被这道页面观察门槛误挡。

如果操作已经提交，或暂时不能确认是否提交，Agent 会如实保留这个状态，先检查结果，不能把“未确认”说成“没有执行”，也不能照旧位置再点一次。暂时读不到页面时，可以尝试其他已提供且已授权的观察方式，或切换到合法屏幕再观察；不会虚构工具或绕过拒绝。用户停止、权限撤回、安全限制、超时和存储失败仍按各自规则处理。

这轮实现已通过源码测试：Runtime **109 项**、页面脚本 **55 项**和集成类型检查。Runtime 测试使用真实 Pi 与三种协议的受控 SSE，验证旧动作被拒绝后，在同一个任务、同一个 Agent 中读取新截图／组件树，再执行新动作；还覆盖不同任务隔离、未知提交状态、陈旧读屏、停止、撤权和失败边界。

上述结果属于 Node／受控平台端口验证，尚未完成这份修复对应安装包的模拟器或 Thor 真机验收。后续运行层诊断改动也不自动包含在本次测试结果里。固定源码哈希、日志及范围说明见 [页面变化恢复测试证据](../tests/release-0.8-evidence/target-recovery/README.md)。

后续已在保留这 27 项恢复回归的基础上补齐停止边界，全 Runtime 达到 **115/115**；界面进一步合并重复恢复提示、成功观察后清除动态提示，AppJS 达到 **58/58**。统一 JVM／lint／debug 和 release 构建、产物隔离检查也已通过，固定范围见 [后续软件快照](../tests/release-0.8-evidence/software-target-recovery/README.md)。这些软件结果不替代真实窗口或游戏操作验收。

## 目标观察失效与真正后端故障的分类

真机 game-12 的一次只读数据库检查，在 100 条工具结果中发现 22 次 `BACKEND_UNAVAILABLE`：这些调用在对应请求的工具列表里原本可用，但全部没有进入 `tool_intent` 或 `tool_started`，所以拒绝发生在 Runtime 首次执行前校验，未进入设备资源锁、手势提交或 `ACTION_CLICK`。这组旧记录没有保存当时完整的 availability 原因，不能据此逐条断言硬件故障的具体类型；它暴露了“观察失效造成有效工具列表收缩”会被包装成泛后端错误的分类缺口。

新增的 Native `reasonCode` 只用于固定分类。真实后端缺失、未授权、不支持或未知未完成手势的非就绪状态保留原优先级，不会被目标检查覆盖。后端就绪时，输入目标观察的明确 `TARGET_CHANGED` 仍保持非就绪状态，同时携带这个代码；权限、安全内容和显示器丢失则保留各自的固定拒绝类别。字段不会授权输入，也不会延长快照／Presentation 凭证寿命。

Runtime 仍从有效工具集合中排除所有非就绪项。只有受审计的 Native 屏幕输入工具，其自身前置条件明确报告 `temporarily_unavailable` 和 `reasonCode=TARGET_CHANGED`，才进入既有“重新观察并继续”流程；文字描述、未知代码、其他工具的前置条件、普通忙碌、真实后端缺失均不能触发该转换。停止、会话／权限代次变化、能力撤销仍先执行；已经到达 Native 的权限、安全内容和显示器拒绝不会被后来变化的 availability 改写。旧坐标、截图、节点、资源锁和最终提交守卫均保持原规则。

此窄修复已通过 TypeScript 编译、新增 **43 项**三协议真实 Pi／受控 SSE 回归，以及全 Runtime **182/182** 测试（零失败、零跳过）。测试覆盖执行前拒绝没有 Native intent、保持同 Run／Pi 读取新截图后继续、不重放旧操作、未知／忙碌原因不恢复、权限与停止优先级，以及 Native 硬拒绝的类别保留。新增 6 项 JVM 投影边界测试已落盘，等待统一构建执行；当前尚无此修复对应 APK 的模拟器或真机结果。固定源码／测试哈希与软件日志见 [独立分类证据](../tests/release-0.8-evidence/target-availability/summary.json)。之前的 App `429ffa7d…` 真机与 Presentation 结果不包含这份新修复。


## Native 成功回执中的空错误字段

后续真机 game-13 暴露了一处接口形状差异：Native 成功回执明确包含 `error: null`，而原 Node 端口大多省略该字段。此前纯读拒绝判断只排除 `undefined`，误将这类成功截图／选屏当成失败，丢弃正文并产生非法空错误码。现在统一规范化回执错误：`null` 与省略字段均为成功；只有固定 `ErrorCode` 才是有效错误，未知非空值按 `PROTOCOL_ERROR` 拒绝且不交付正文。该规范化值同时用于读取拒绝、事件、Pi 的 `isError` 与观察门槛，避免局部判断不一致。`RuntimeError` 构造器也校验固定码，阻止未知 Native 桥接错误扩散为非法运行状态。

新增 **31 项**回归明确使用 Native 形状的 `error:null`，在三种协议的真实 Pi／受控 SSE 中完成“选屏成功→旧输入仍被观察门槛拒绝→截图成功→下一请求含图片→新输入成功”；还覆盖换源丢弃、停止优先、未知错误正文不泄露，以及已提交回执不丢失。全 Runtime **213/213**、TypeScript 编译及打包通过，原权限／安全／显示器和 typed-target 回归继续通过。源码已冻结，尚待 Root 对对应新 APK 验收；独立软件哈希和日志见 [空错误字段回归证据](../tests/release-0.8-evidence/native-null-success/summary.json)。没有为此扩大其他字段的可空契约，也没有修改 Native 输入守卫或执行架构。


## 保留旧失败历史后的冷恢复

game-13 的旧失败 turn 留下了一条 `perception_select_screen` 工具结果，其 `content[0]` 为 `{type:"text", text:null}`。下一次冷恢复虽然没有重放操作，但 Pi 在发送 HTTP 之前转换旧历史时失败。三协议复现均得到 `MODEL_STREAM_FAILED / IO_ERROR`、零 HTTP／零 Native 执行，以及读取 null／undefined 的 `length` 异常。此前只修新回执的 213 项软件快照保持原样，不能代表这项旧数据兼容已通过。

现在使用显式 `projectHistory` 投影，仅将**历史 tool_result** 中 `type=text` 且正文为 null／缺失的项显示为“此前结果正文不可用，请重新观察当前状态，不要重放旧操作。”。原始 DomainTurn 和数据库不写回，完整 turn、工具配对、原 `isError`、已提交副作用记录、约束及其他正常历史均保留。冷恢复与后续历史编译使用同一入口；没有在当前 turn 保存函数中做这种修补。历史用户非法文本、历史非空但错误类型的工具文本，以及当前用户／工具非法正文仍严格拒绝。当前工具文本在编码前验证，避免把 null 隐式变成字符串 "null"；已经提交的回执仍保留。

修复后，原六项冷恢复复现全部变为 completed，并各产生一次真正 Pi HTTP 请求、零旧工具执行；原 HistoryTurn 的 JSON 比较保持完全一致。新增 **22/22** 聚焦回归与全 Runtime **235/235**、TypeScript 编译和打包通过，包含撤权历史过滤与当前严格拒绝边界。独立 [旧历史兼容软件证据](../tests/release-0.8-evidence/legacy-null-history/summary.json) 分别保留真正 before/after 日志与 setup 失败记录，不将 setup 失败当复现。新 APK 验收由 Root 单独固定产物和记录；这里不声称已跑通真实游戏目标。
