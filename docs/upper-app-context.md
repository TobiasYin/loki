# 默认上屏应用基础信息

开启会话的屏幕感知后，每次模型请求自动带入校准上屏当前可见应用的包名、真实名称、版本名称与版本代码，无需先调用 `perception.app_info`。前台对象每轮重新观察，静态 PackageManager 基础信息最多缓存 60 秒、16 项。查询不到名称时省略名称，不把包名伪装成名称。

`l0.upperApp` 始终指上屏，`targetScreen` 仍表示当前 Run 选择的操作屏幕；选择下屏不会把上屏信息替换为下屏应用。未获得可靠 Activity 名称，因此不注入猜测的 Activity。未知、不可访问或有歧义的状态通过 `upperAppObservation` 表达，不沿用上一次应用数据。

信息只作为观察上下文，不提供输入快照、控件引用或额外执行权限。关闭或撤销屏幕感知后不再读取、发送这些信息，配置探测也不额外读取。由自动感知信息推导的历史回答保留来源标记，撤权后不会继续发给模型。应用标签属于外部数据，不是指令。

Native 在包信息读取前后复核上屏及窗口身份。标签和版本名称按 Unicode／UTF-8 边界限定长度，版本代码用字符串保存以避免 64 位整数精度损失；模型基础上下文保持不超过 1 KiB。自动注入不会改变现有输入目标和窗口保护。

AYN Thor / Android 13 真机验证一轮通过：正式产品工具完成中文与 Emoji 替换、插入、清空、Enter、重新聚焦、Ctrl+A 与 Backspace，独立接收端确认实际效果。另用设备保存的真实模型配置，仅要求回答默认上屏基础信息，提示中不提供期望值。模型完成回答、调用工具 0 次，应用名称、包名、版本名称和版本代码均与 PackageManager 一致。

真实上下屏夹具同属 Input Lab，该真机阶段验证选择下屏时上屏观察仍为 display 0、信息与 PM 一致；不同包来源由 Native 单元测试及 Runtime 三种协议场景验证，不把同包真机案例描述成不同应用的跨屏验证。

测试结束保留原始 191 个运行和全部历史记录、原选中会话、凭据及配置；新增两个测试运行均终态。手动 Native 组件没有执行模型回合，因此其常规结束记录为 Runtime 未完成，不能混记为真实模型请求失败；真实模型运行已 completed。测试夹具退出，上屏恢复原首页，正常 Launcher 验证助手默认回到下屏 4。
