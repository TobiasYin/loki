# 官方模型预设、能力切换与响应速度

## 预设与真实连接测试

OpenCode Go 和 DeepSeek 官方预设使用服务目录中的模型参数。保存对应服务的 API Key 后，在会话选择模型即可发送，不再要求先运行图片／工具探测。`profile.check` 返回 `provider`、`configured`、`metadataKnown`、`probeRequired`、`probeNeeded`；未填写凭据仍属于未配置，服务端鉴权和网络错误按实际请求反馈。

这不会写入假的 `probe=passed`。`lastProbe` 仍仅表示本机实际完成的连接测试。显式测试使用 Native 授权的独立 `configurationProbe` 运行标记，测试开始时不需要宣称自己已经通过；结束后才依据实际网络、文本和工具／图片往返记录结果。自定义服务继续保留真实连接探测要求。官方 provider 名称如果搭配自定义地址，也不能继承官方免探测资格。

模型参数按当前所选模型生成：协议、文本／图片输入、工具调用、思考能力和支持的 effort、上下文窗口，以及最大输出能力。`maxOutputLimit` 表示目录声明的模型输出上限；`maxOutput` 是用户设置的本次输出预算，不超过模型上限。文字模型不会被标为支持图片；未声明工具调用的官方模型仍可进行文字聊天，但不发布工具。DeepSeek 默认 effort 采用官方配置的 `high`，`off` 映射服务的 `none`。

## OpenCode Go 参数来源与离线行为

OpenCode 官方文档说明模型目录来自 [Models.dev](https://opencode.ai/v2/docs/models)。实现组合两个公开来源：

- [OpenCode Go 服务模型列表](https://opencode.ai/zen/go/v1/models)：当前公开模型 ID；目前该接口本身不返回能力参数。
- [Models.dev 参数目录](https://models.dev/api.json)：`opencode-go` 的模态、工具调用、思考选项、上下文和输出限制。

取两者交集，保留客户端实际支持的协议；缺少必要参数或协议尚未实现的条目不凭空补全。官方目录声明的音频、视频或 PDF 等其他模态保留在 `providerInput` 资料中，不将其当作本客户端已实现的输入能力。Pi 已验证的协议及参数映射作为传输兼容资料，其中保留用户已确认可用的 Go DeepSeek Responses 路线；它不覆盖官方模态和工具能力事实。切换至 Anthropic 协议时，仅给 Pi 的 Go base URL 去除末尾 `/v1`，由 SDK 追加一次 `/v1/messages`；Responses 和 Completions 保持原基础地址，避免协议切换产生重复 `/v1/v1/messages`。

刷新仅由设置页面明确发起，切换模型和发送任务不等待目录联网。刷新结果通过校验后整体写入版本化缓存；失败保留原缓存。旧版或损坏缓存不冒充完整官方参数，退回随 APK 携带的 2026-10-16 同源目录快照。来源标签区分在线缓存和内置快照。缓存只含公开模型资料，不保存 API Key。

## 会话标题和能力开关

新会话标题保留第一条用户消息的首个非空行，不再固定截取 10 个字；保留完整 Unicode 字符，在 512 个码点以内存储，视觉省略由页面宽度决定。既有用户标题保持原样。

能力命令带 `clientMutationId`。Native 返回有界 `capabilityAcks`，每个会话／能力保留最后一条确认，字段为 `sessionId`、`capability`、`clientMutationId`、`enabled`、`ok`、`error` 和 `capabilityRevision`；会话快照也包含版本号。前端先展示用户选择，只用匹配的确认提交或回滚，不用旧快照覆盖新操作。

相同值的重复请求只确认，不重复停止任务或写库。实际变更继续撤销该会话旧授权并停止其相关运行，避免旧权限复活；只持久化目标会话和受影响的运行。没有更改其他会话、历史消息或工具证据。

## 本地流式开销

原先每个流片段都同步持久化并重新构造整段选中会话视图，能力变更还会全量比较历史表。新的本地路径保留完整持久化语义，同时减少重复工作：

- 会话修改仅更新对应会话行；运行流更新仅更新所属会话和运行，不反复写其他会话。
- `ChatEventProjection` 只折叠新增事件；历史流事件保持完整，显示端继续聚合思考与文字，并保留最新工具参数。
- Native 的文字、思考和未完成工具参数显示合并在 50 ms 窗口内；关键状态、工具结果和批准请求立即发布。
- Runtime 在进入 Native 前再合并同一文字／思考块的细小片段：首片立即保存，后续按 40 ms 或 4096 字节阈值批量保存；这个阈值不是单事件大小上限。状态、完整工具参数、执行意图和工具结果前先按顺序清空。落盘失败会停止上游请求，不能继续设备操作。
- UI 命令只生成一次返回快照，避免同时返回和通知各自重算。
- 会话未启用的能力不在启动任务时同步探查其设备后端；实际启用的工具提交时继续执行授权、目标和系统状态校验。

这些改动减少本地等待，不将真实云端推理或多次模型往返计为已经消除的延迟。实际模型首响应和长流程完成时间仍需对应服务、设备与任务的独立验收。

真实 Citra 长流程还触发了两处旧限制：审批工具超时后仍处于 awaiting_user，下一轮请求被误判为协议错误；Native 将 32 个在途工具的预算误当成累计调用预算。现在工具结束会退出审批等待，但用户停止不会恢复请求；在途 payload 完成即释放，已消费标识另行有界保存以拒绝重复执行。连续 80 次读取与并发单次领取另有回归，单轮模型请求预算扩展为 256 次以支持长程双屏操作，仍有有界请求／响应大小、单工具期限及原会话续接。

## 回归范围

JVM／Node 回归覆盖官方与自定义资格区分、未测试官方模型直接启动、真实探测记录不伪造、文字／无工具模型、官方目录和缓存异常、完整首行标题，以及 20,000 条流事件后的增量更新与视图隔离。`ScopedSessionStorageTest` 使用随机临时数据库和拒绝无关会话更新的 SQL trigger，验证能力／运行写入只触及所属会话且保留历史。`EmulatorDeepSeekSettingsTest` 还通过真实 Native 新会话、`profile.check`、begin/end 检查官方预设不被旧探测状态阻挡，不发起真实云请求。

运行时完整 Node 回归包含未探测官方文字模型不发布工具仍能回答、真实 Pi Anthropic 本地流请求路径只有一次 `/v1/messages`，以及审批超时后继续、用户停止不续跑和定时聚合落盘失败中止。这些软件回归不冒充对应官方模型的真实云端验收；本轮计数与对应构建见 `tests/release-0.8-evidence`。

## 真机既有长流程的延迟观测

本轮修复前后分阶段采集的真实 Go 请求说明，慢的来源不能只归为 APK 启动。以下来自 `game/progress.json` 的不同历史 Run，不是同包前后对照基准，也不代表新后台版本的真机速度：

| 观察轮 | Native 准备 | 首次权限／目标快照 | 首个 HTTP 响应头 | 首次可见文字 |
| --- | ---: | ---: | ---: | ---: |
| game-02 | 19 ms | 32 ms | 3,620 ms | 4,270 ms |
| game-04 首轮 | 53 ms | 87 ms | 11,626 ms | 12,212 ms |
| game-08 最后一轮 | 91 ms | 235 ms | 13,233 ms | 未记录 |

HTTP 响应头等待包含传输和服务端等待，不能仅据此分解成网络延迟或模型推理时间。可见文字还会受到思考先行的影响；没有可见文字不等于没有收到流。长流程不断往返模型，工具拒绝后的重试与只看上屏造成的错误判断又增加了调用次数。当前软件优化减少本地写入和渲染等待，新增下屏观察、选屏与后台工具解决信息缺失；真实新包是否缩短完整游戏任务，仍需 Thor 重连后在原会话继续验证。

## 动作回执与执行后的页面变化

Thor 的 game-10 实测确认：4 个 Native 已提交回执（启动 1、坐标点击 2、语义激活 1）在页面变化后，被 Runtime 用旧目标／工具 availability 再检查，误标为 BACKEND_UNAVAILABLE/unknown。这些动作并非未执行；实际 effect ledger 保留 submitted 和证据引用。维护停止保留原会话，Citra 的 34 个既有 sdmc/nand 文件逐字节散列与本轮前一致。

现在执行前三处工具权限、发布状态、availability 和目标检查保持；接收结果时检查当前 Run/Session/lease/epoch、停止状态和所需能力，不把成功动作造成的页面变化当作执行失败。纯屏幕读取仍拒绝请求源被无关替换后的正文；异步附件解包后再次校验。已收到 Native 回执后才撤权／停止，保留最小 outcome/evidenceRef，丢弃正文，不重放动作，也不在终态后异步写回。

新增 15 项真实 Pi＋本地受控 SSE 回归覆盖 Responses、Completions、Anthropic 下的启动／点击／激活、同 Pi 追问、执行后撤权和停止、附件期间撤权、纯读取跨目标、选屏身份与执行前拒绝；Runtime 总计 82 项通过。新包后台两项另外通过，具体固定安装包见 [后台运行](background-runtime.md)。真机 game-11 已在原会话继续，Agent 自行 background、选下屏、截图和语义输入均已出现真实成功回执；不据此宣称已完成新档或游戏任务。
