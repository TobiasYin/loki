# Long-task recovery: software verification point

The fixed long-task-recovery build combines typed screen-target availability with bounded Native/chat display projections, retaining the separate never-attached execution document. Its independent software record is [`software-long-task-recovery`](../tests/release-0.8-evidence/software-long-task-recovery/README.md). The previous split-document record remains unchanged and describes its own package.

The Native event path previously appended a fragment to the in-memory ledger before rejecting accumulated message thinking/text above 65,536 UTF-16 units. That made a display limit capable of surfacing as a persistence failure during an otherwise legal long stream. The new path validates incoming event/commit identity and data before mutation, retains each complete durable fragment, and keeps a bounded recent tail only for chat display. Native message metadata (`textTruncated`, `thinkingTruncated`), projected stream metadata (`data.textTruncated`) and omitted-length counts identify this display projection. Chat shows a muted truncation indication, renders the recent thought content when expanded, and does not build a large hidden thought body while collapsed. A surrogate pair is never split at the displayed tail boundary.

This change does not truncate Pi messages, DomainTurn context or the durable event ledger. A cumulative stream or legal individual delta can exceed the display bound and still reach a normal completed commit. Regressions also verify that invalid delta/commit input cannot append an event or mutate the prior message/run first. The raw event history remains subject to the existing genuine storage and resource bounds; this is not a claim of unlimited storage.

The historical game12 record retained 65,511 UTF-16 units of thinking, just 25 below the old display bound, and a complete durable set of 108 tool calls and 108 matching results. Its retained turn was about 222 KB, rather than near the 16 MiB turn limit. Together with the old event-path ordering, this strongly identifies the cumulative display bound as a relevant failure path. The exact next rejected fragment was not recorded, so the regression establishes the corrected boundary without claiming an exact reconstruction of that missing fragment or every earlier stall. No private thought text or full event payload is published here.

The availability change separately preserves a fixed Native target-error classification. Only the narrow Native screen-input prerequisite carrying typed `TARGET_CHANGED` requests a new observation. Real backend unavailability, capability/session/epoch/cancellation checks, and Native permission/secure/display refusals retain their existing priority. An availability classification does not itself authorize or dispatch input. The accompanying real Pi/controlled-SSE tests cover recovery across three protocols; they are software tests rather than a cloud or physical game result.

Actual retained XML contains 398 passing JVM tests with no failures/errors/skips; App90, device-core180 and device-authority13 executed, while core41 and Input Lab74 were UP-TO-DATE. Runtime182 and Chat69 passed, and integration TypeScript succeeded. Bridge13 and relay3 are explicitly retained prior checks, not a new test run. Lint retained 106 warnings and no Error/Fatal entries. Exact log/source/XML hashes, artifact identities and cache status are in the independent software record.
