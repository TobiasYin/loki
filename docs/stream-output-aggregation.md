# 流式文字重复展示与事件聚合（2026-10-18）

## 原因与真机证据

真机当前长任务首次检查时有 925 条事件，33 个文字片段共 607 字符；任务结束后有 1,273 条事件，文字共 1,334 字符。两次检查中，事件文字拼接均与 Pi 原生 Assistant 消息逐字一致。此问题不是同一 Native 快照被 DOM 反复追加，也未发现已检查文字被重复入库。

原页面只读取最近 600 条执行事件，却拿这部分文字与整轮累计 `message.text` 比较。窗口移出旧文字后，两者不相等，页面就退出按时序分段展示，回退显示整轮累计文字；已经折叠的阶段消息因此重新出现在正文，后续汇报又不断加长正文。

## 展示修复

`SqliteStore.loadChatPage` 为当前可见的任务单独提取 `text_delta` 文字，按真实 `blockId` 重建 `run.textSegments`。总预算每轮 65,536 UTF-16 单元、最多读取 2,048 个文字记录，保留最近的尾部与完整 Emoji 边界；不加载 Pi 历史、旧思考或图片体。SQL 查询不依赖 JSON1，兼容 Thor 的 SQLite。

页面有该字段时将它作为权威文字来源，删除普通分页事件中的文字副本，再按首序号插回思考和工具时序。即使事件窗口为零或最后 600 条完全没有文字，也不会回退显示整轮累计正文。同一 Assistant 消息的相邻内容块可以合并，下一条真实消息则独立分段。折叠时只显示最后一条，展开后旧消息仍按时序查看。缺少真实分块标识的旧格式保留兼容兜底。

## 聚合存储

后续流式提交只将同一 session/run、类型、非空 `blockId` 且源序号连续的文字或思考增量合并到同一数据库行。保留首身份与首序号，以 `lastSequence`、`lastEventId`、`fragmentCount` 记录末状态和片段数。工具、状态、授权、结果和错误事件保留独立记录，不跨边界合并。

每个聚合行文字最多 128 KiB UTF-8，超过时另起行，持久化文字不截断，不使用字符串前缀去重。全量和部分状态保存也采用相同聚合规则，防止将原始片段重新插回。流式事务拒绝重复或倒序的源序号，失败时父记录、消息和选择一起回滚。聚合内部片段的 ID 不再逐个建立独立持久索引。

现存旧记录可以直接读取，不在启动或查看时批量改写。Pi 会话、工具权限和上下文管理保持原有实现。
