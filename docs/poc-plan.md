# Thor 实机 PoC 计划

**所有 PoC 状态：未执行。** 本次仅写计划，不创建测试应用、不安装依赖、不构建 APK、不连接或修改设备。以下步骤只在后续获得开发/测试授权后实施。

## 通用前置与证据

准备 Thor 实机、用户选择的固件、独立 [Thor Input Lab](input-lab.md) 测试 APK（后续授权开发后提供）、测试模拟器/游戏与合法测试内容、可恢复配置副本、用户提供的两个模型服务和搜索服务。记录 SKU、Android/API、Build、WebView 包名/版本、上下屏映射、无障碍配置、Shizuku 版本/UID、目标应用版本、Pi commit/发布包锁定信息。

每项结果记录：日期、操作者、环境指纹、步骤、期望、实际、脱敏日志/接收端事件、截图（如需要且允许）、通过/失败/不确定、缺陷和下一步。只看工具返回 true 不作为系统效果证据。测量原始数据与摘要分开；没有结果就保持未验证。

先完成显示与人工输入的基本环境检查，随后执行 POC-11 接收器资格验证，再将其报告作为其他输入/感知用例证据。手动和 Agent 复用 LAB 用例、版本与判定；网络/搜索测试仍使用独立服务。POC 编号保留稳定，不代表执行先后。

## POC-11：Input Lab 接收器资格验证（所有相关输入测试前置）

开发产物为独立上屏 APK；先无需 Agent/自动化 IPC，用实体手柄与手指验证原始事件、控件状态和报告。核对 LAB-01/02/06/07/13/14：一次输入不重复计数、历史样本保留、错误来源/错误靶点/不动作能失败、semantic-only 不冒充触摸、失焦不伪造释放、重启/溢出不出完整通过报告。

后期增加受限测试控制通道后，补验未知调用方拒绝、reset 仅能在未记录时执行、报告读取不抢焦点、旧 lease/旧版本拒绝、模型无 setup/判分接口。通过后记录 receiverQualificationVersion；接收器判定或场景版本变化需重跑相关验证。

通过门槛：正反例判定正确，原始事件/状态可追溯，异常明确 fail/inconclusive，手动与 Agent 同格式结果可比较。失败则阻断基于该接收器的其他通过结论，不能用“测试工具可能有问题”跳过。

## POC-03/04：最小可复现实验

先准备固定响应：纯文本中文、一次无副作用 echo 调用、返回一张非敏感合成测试图的工具、故意残缺 tool JSON。用多个 chunk 边界重复同一内容，比较最终模型消息和事件顺序是否一致。

使用两种协议分别验证：用户图片→回答；工具图片→下一轮回答；工具关闭后 provider request 中无该定义；HTTP 401/403/429/500 body 可供 JS 判断；header 前取消、body 中取消、结束/取消竞态；request body 大于限制；JS 消费暂停后的缓冲上限。

原生传输使用随机非模型流也能通过，证明不依赖 SSE/模型语义。强制阻止 WebView 直连探测旁路；API Key 使用测试秘密值检查 JS、日志、数据库与导出中是否出现。记录桥复制次数、图片峰值内存和首增量延迟。

## POC-05：撤销实验的线性化点

在“模型开始输出工具名”“工具已排队”“资源锁前”“系统调用前”“已提交系统调用”“结果交付前”设置观察点。每点关闭能力，再重开、切 Session、撤销系统授权并重复。判定以 Native 提交授权版本的时刻为准；已提交系统动作不能逆转，但之后任何新业务动作必须拒绝。

初值每个关键竞态做 100 次重复，要求零越权副作用。释放本 Run 卡住输入属于允许的清理；必须单独计入事件，不当作业务操作漏报。

## POC-07：手柄接收证据

在通过 POC-11 的独立 Input Lab 中，由人工 API 与 Agent 分别驱动同一套 LAB-06～10。分别测试：ABXY、肩键、方向键、双摇杆、扳机、两键同按、轴与按钮同时、释放归零。记录接收端设备识别/运动范围、native gamepad/joystick source，而不是仅看到 UI 动了。

对比“下屏聊天未聚焦”“正在打字”“键盘已收起”“用户刚触摸上屏”四种状态。Shizuku 断开/权限关闭/Run 停止后持续观察是否卡键。无法注册合适设备身份或被模拟器过滤即失败，不把额外 Root 修改纳入默认通过条件。

## POC-08：恢复实验

先只操作配置副本，然后在有恢复路径的目标配置上测试。故障点：备份前/后、临时写中、提交前/后、校验中、恢复中。注入磁盘不足、路径变符号链接、目标并发改动、SAF 授权丢失、进程终止。每次记录现存文件 hash 与可恢复备份；未知状态不得自动重试写。
