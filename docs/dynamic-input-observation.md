# 动态画面中的输入目标校验

光标闪动、计数器变化和游戏正常绘制，不再仅因为内容版本更新就拒绝坐标或手柄输入。输入依据当前应用、窗口、屏幕与交互布局是否仍兼容，而不是要求旧截图与当前画面内容完全相同。

| 变化 | 当前处理 |
| --- | --- |
| 普通文字、光标选择、计数器、同窗口动画，以及纯标题／无障碍焦点窗口通知 | 保留内容更新记录，稳定目标上的新输入仍可执行 |
| 列表实际滚动、明确的子树重排 | 后续旧坐标失效，重新观察；已经提交并引起这些反馈的滑动可正常完成 |
| 真实窗口／应用／屏幕切换、遮挡、真实焦点变化、过期或撤权 | 保留原有拒绝和重新观察／停止处理 |
| 指定节点本身的路径、身份、文字签名或位置发生变化 | 旧 nodeRef 继续拒绝；无关控件更新不影响稳定节点 |

实现把捕获内容版本、交互布局版本和稳定窗口结构分开。读取和已提交的持续输入不会因自身滚动反馈而被中断；新坐标仍检查交互布局。手柄仍核对实际输入路由的屏幕和应用，坐标仍须位于原、新可触区域的交集。原先仅适用于唯一全屏窗口的几何归一化条件保持不变，没有增加像素容差，也没有增加新的完整裁剪相等要求。

截图保留原 `captureSnapshotId` 与真实像素来源。即使捕获过程中发生普通内容更新，只要窗口、坐标变换和交互布局兼容，返回的 frame 仍可用于输入；滚动或重排后的旧 frame 不会借新的观察重新变为可输入。`contentChangedDuringCapture` 表示观察到的内容版本变化，不是逐像素相等测试；纯 Canvas 动画可以没有无障碍通知。

Android 事件分类采用 `windowChanges` 和 `contentChangeTypes`：纯 TITLE／ACCESSIBILITY_FOCUSED 窗口标记不再撤销稳定窗口证明；真实、混合或未知窗口标记仍按结构变化处理。SCROLLED／SUBTREE 使用独立交互布局版本，不撤销未改变的物理窗口证明。通知类型和位定义参考 [Android AccessibilityEvent 文档](https://developer.android.com/reference/android/view/accessibility/AccessibilityEvent)。

可用工具投影中明确的目标拒绝原因按 Run 保存，并在下一次观察时整表替换。因目标变化而暂时取消发布的工具，在准备执行时仍返回 `TARGET_CHANGED`，以便现有恢复流程重新观察；明确的权限、受保护内容和屏幕丢失原因保留各自错误码。能力关闭、模型不支持工具、未知工具或无明确原因的后端故障不会因此获得发布或执行权限。

新增 DEBUG 普通 Activity 场景包含固定尺寸计数器、逐帧动画、真实光标、固定按钮与原生滚动列表。组件验收通过正式 Native RPC 操作真实窗口和输入，接收端独立记录触摸、点击与滚动；它不使用模型、不操作 Citra，也不代表真实游戏长程目标已完成。

软件验证共 446 项 JVM 检查通过，无失败、错误或跳过。其中 App 117 项、Input Lab 74 项为最后一次构建执行，其余 255 项为同构建链中的 UP-TO-DATE 结果；新增 5 项发布拒绝原因回归包含在 App 117 项中。模拟器动态输入组件第三次验证通过，聊天界面组件回归也通过；此前两次失败均保留独立产物和报告：第一次测试内容不足以滚动，第二次在弹窗拒绝错误码及清理断言处失败，不将这些结果计为通过。

本轮最后检查时，5037 端口未检测到 Thor。最终 APK 已生成，真机更新、实际游戏动态画面和 Citra 长程操作待连接恢复后验证。完整构建与分次验收记录见 [动态输入验证记录](../tests/dynamic-input-evidence/README.md)。
