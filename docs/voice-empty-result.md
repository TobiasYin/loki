# 无语音识别结果的正常收尾

按住说话但没有检测到人声，属于一次没有产生文字的输入。松手后恢复“按住说话”，不显示错误、不发送空消息，也不把此前不确定的临时文字作为消息发送。原有普通文字草稿保持不变。

分类依据火山返回的固定数值码，不根据错误文案猜测，也不因没有识别文字而隐藏真正的连接故障：

| 返回结果 | 处理 |
| --- | --- |
| `20000003` 静音，或兼容流式接口的 `1013` 未识别出文字 | 正常无语音终态，清除本轮语音临时文字 |
| 成功终态中识别文字为空、null 或缺省 | 正常空结果，清除本轮语音临时文字 |
| `45000002` 没有收到可供识别的音频 | 提示检查麦克风或音频输入；它不等同于检测到静音 |
| 参数／音频格式错误、鉴权失败、等包超时、服务繁忙、未知服务码 | 保留真正错误，使用固定的友好文案和必要的错误码 |
| 断网、HTTP 失败、畸形协议帧 | 保留连接或协议错误，不伪装成无语音 |

二进制错误帧和 JSON 结果中的状态码采用同一分类。在识别静音之前，必须先验证报文长度、压缩、编码及声明的 JSON 格式；仅有某个静音码的截断帧仍然是协议错误。服务端原始错误正文不直接显示到界面。

有效终态先于松手到达时，录音源可以结束，但仍由用户松手完成本轮输入。第一份有效终态冻结本轮语音结果；随后重复消息或连接关闭不能重新生成文字，也不能把已经有效完成的识别改成网络错误。终态前的真实错误仍然提示，取消后不发送。

参考火山官方[错误码查询](https://docs.volcengine.com/docs/DoubaoVoice/error-code-query?lang=zh)、[大模型流式语音识别 API](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelstreamingautomaticspeechrecognitionAPI?lang=zh)和[兼容流式识别错误码](https://docs.volcengine.com/docs/DoubaoVoice/Streamingautomaticspeechrecognition?lang=zh)。实际使用的端点与原配置保持一致。

验证范围分开记录：JVM 协议与真实本地 WebSocket 回归、页面 JavaScript 回归、模拟器界面检查，以及使用真机已保存凭据向火山发送生成的全零 PCM。最后一项不使用物理麦克风，不发送模型任务，不替代真实声学或完整 UI 长按验收。
