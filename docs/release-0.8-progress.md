# 0.8：官方模型、交互效率与真实游戏长流程

本轮软件变更已进入回归。2026-10-17 用户重新连接 Thor 后，已备份当前资料，保留原会话安装后台／双屏新版，并通过正常发送入口恢复真实 Citra 任务。game-10 暴露动作返回后的旧目标误判，修复后在同一会话继续 game-11。后者进一步确认 Citra 下屏为 Android 13 未映射的 Presentation 窗口；维护停止已撤销 Native 权限，但执行状态未收敛，备份后仅终止助手自己的测试进程并冷恢复原会话。模型配置、加密凭据与已保存上下文保留，没有主机游戏输入或数据库／游戏文件编辑。具体等待根因尚未确定。不要将 instrumentation 的观察器成功视为游戏目标成功；`goalIndependentlyVerified=false` 保留到逐项核对游戏画面。

## 软件变更

- 增加 DeepSeek 官方预设，填写对应服务 API Key 后下拉选择模型。官方目录参数、实际连接测试、密钥隔离和验证范围见 [DeepSeek 官方接入](deepseek-official-provider.md)。没有可用的官方服务密钥时，本地受控 SSE 测试不冒充真实 DeepSeek 云端验证。
- OpenCode Go 使用服务模型 ID 与 Models.dev 参数交集。已知官方模型选择后可以直接发送，自定义地址仍需实际连接测试；不会伪造探测通过记录。
- 输入区模型和思考选项使用自定义键盘可访问下拉框；思考、工具详情采用可中断的展开／收起动画，尊重系统减少动画偏好；普通待执行意图不显示成红色未知结果。
- 新会话标题保留首个非空行，显示宽度决定视觉截断；能力选择先即时反馈，再按匹配的操作编号确认或回滚。
- 减少历史全量重建、全表保存、细小流片段逐条跨桥等待等开销；审批超时后的状态恢复与累计调用预算修复见 [模型参数与速度](model-presets-and-response-speed.md)。
- 页面变化返回可恢复的工具结果：同一运行重新观察后继续，不自动重放旧动作。主消息区只显示一条当前恢复提示，成功读取新观察后清除，未知提交事实保留。规则和源码测试范围见 [页面变化恢复](target-change-recovery.md)。
- 显式停止补齐 provider 事件流与请求体等待的取消边界，等待真实 Pi 回到空闲后保存部分上下文；没有增加模型总时限。调试诊断只暴露阶段、数量与耗时，见 [停止与诊断](stop-boundary-diagnostics.md)。

## 从真实卡点增加通用工具

`perception.find_apps` 只查匹配应用，`apps.launch` 只用真实公开 launcher 启动当前任务选定屏幕上的应用。指定应用查找不需要读取完整安装清单，原 Shell 灰名单没有放宽。组件测试与模型实际前台启动分别记录。

`input.navigate({action:"back"})` 发送固定 Android BACK，显式路由当前选定屏幕，并核对目标显示器自己的 focused application/window。全局物理手柄焦点与显式显示器路由不是同一条件；物理手柄工具仍保留原焦点验证，不擅自改变系统焦点锁。

动态界面的文字计数可能不断产生内容事件。读取允许这种内容更新，但仍严格验证窗口、包名、焦点结构、显示角色、epoch、有效期和完整可触区域。截图的拍摄身份与完成时身份分开；内容改变时旧像素帧不能冒充新的可点帧。

对 Android 13 将真实 Presentation 报成 Accessibility `-1` 的情况，新适配通过系统窗口 ID、token、实际类型 2037、包与 UID、可见性和安全属性建立独立证明，保持原始类型与后续输入守卫。未知窗口不能仅凭标题或可读的根节点获得操作资格。边界和独立接收端验收入口见 [Presentation 窗口](presentation-windows.md)。

`input.activate({nodeRef})` 在当前组件树中找到可见、启用、可点击、非密码控件，提交前从当前窗口根重新定位并验证节点自身身份、签名和精确边界。新观察、输入或树失效后引用不可复用。普通坐标输入、手柄和原有滚动守卫没有因无关内容更新而整体放宽。

## 游戏验收方式与进度

`PhysicalLongGameFlowTest` 只通过正常发送入口给 Thor Agent 整个自然语言目标，观察其运行；没有预先启动 Citra、选择 ROM、建立存档或代发游戏输入。目标应用查找、启动、列表选择、游戏菜单和设置操作均由模型工具调用执行。失败后的自然语言追问仍使用原会话；同一观察轮达到请求预算时可在同一 Pi session 继续。

设备实际有多款 Citra 系应用；模型自行选择了名为 Citra 的 MMJ 安装，而不是根据主机预设包名启动。已独立截图确认模型打开目标游戏并调用 Android BACK 打开真实菜单；尚未独立确认创建新档、取得剑或完成开篇任务。测试前已有存档和配置备份仅保存在忽略的私有目录，不提交数据库、凭据、ROM、存档或完整 APK。

软件与模拟器证据分别保存在 [0.8 证据目录](../tests/release-0.8-evidence/)。不同轮次 APK 的指纹和测试范围分别说明，不能合并成未经执行的同包验收。

## 后台和两屏操作

Service 持有同一执行文档、Native authority、数据库 writer 和 Pi session；离开聊天或重建 Activity 时不销毁正在运行的 Agent。用户发送从配置测试到正式任务均持有前台执行状态，通知提供停止所有任务。`agent.background` 只将聊天自身退到后台；之后 Agent 必须重新观察目标应用。运行停止会立即撤销 Native 动作权限，不等待界面停止动画或持久化队列。系统强行停止、进程或渲染器退出不会自动重放任务，恢复时保留为中断历史。生命周期验证及固定包范围见 [后台运行](background-runtime.md)。

`perception.select_screen` 按运行选择 upper/lower；上下屏可为不同应用。新运行默认 upper，切屏不影响其他运行和设备校准。截图、节点和输入均绑定当前屏幕，切换与动作提交在同一 authority 锁下校验，旧屏引用不能在切换后执行。需要操作聊天所在屏幕时先退到后台；禁止操作助手自己的授权和审批界面。两屏 Native 独立接收验证见 [双屏组件验收](emulator-dual-screen-native.md)，它与真实模型游戏长流程分别验收。

后台重构同时修复系统图片／Skill 选择器结果先于异步 Service 连接返回时的崩溃：暂存 URI 与原会话，恢复既有 Engine 后再消费，不创建第二个 writer。

## 启动保存范围与最终临期核验包

新的启动保存路径只在一个事务里写入会话元数据、选中项和启动前捕获的非终态 Run；不为启动比对全库旧 payload，不改消息／事件／截图记录、终态 Run 或数据库结构。旧上下文完整保留，未知或已终态恢复标识拒绝，原失败撤权和重新读取路径不变。三项随机临时 SQLite 验收分别检查历史写保护、metadata 失败全回滚与非法恢复标识；其 Android 执行结果与 JVM 软件检查分开记录。
