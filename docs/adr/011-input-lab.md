# ADR-011：独立上屏测试 APK 作为统一接收端

日期：2026-10-13。状态：已采纳（需求及设计），具体测试 IPC 待验证。

## 背景

仅凭注入 API 返回成功或 Agent 文字不能证明上屏实际收到事件。早期手动 API 测试与后期 Agent 测试若使用不同靶场，结果难以比较，手柄来源、轴、焦点和释放错误也容易被 UI 表象掩盖。

## 决定

在 tests/input-lab-app 规划独立 Thor Input Lab APK：独立包、进程、UID、数据，运行于上屏，记录系统送达原始事件并验证场景状态。两阶段复用版本化场景、预期、容差与报告；先经 POC-11 校准接收器自身，再作输入回归的依据。

测试控制/报告通道独立于被测输入通道；不注入 Agent 工具，不提供写通过、注入事件或直接改变任务结果的接口。接收器不复用输入执行器的坐标/判定实现。真正通过需接收端证据，仍保留真实模拟器兼容性回归。

## 备选与取舍

只用日志/截图不足以验证完整原始输入；把测试页面放在 Agent 自身进程不能证明跨应用分发；只用游戏会使事件细节和可重复断言难以获得。因此选择独立可重复接收端，而非替代真实游戏验收。

早期应用内 arm 和导出即可，不阻塞于自动化 IPC。后期首选签名权限保护的 bound service，显式组件与测试 lease；正式包名/签名在 Q-18 冻结。日志中的 source/deviceId 不视为输入发送者的认证证明。

## 后果与门槛

增加一个仅测试使用的独立 APK 及报告版本维护成本，提前到 M1a。未经接收器自检的结果不能进入发布证据；漏事件/崩溃/失焦要明确不确定性。此 APK 不新增 Thor Agent 的产品能力开关，不改变 Shell 的跨能力边界。
