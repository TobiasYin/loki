# 安全边界与信任模型

> 2026-10-13 状态更新：五模块已开发并进入正式软件整合。本文早期“仅规划/未授权/无 APK”等叙述保留其历史背景；当前实现、实际测试与尚未完成的 Thor 验收，以 [中文集成报告](integration-report.md) 为准。来源模块旧测试不等于本次集成结果。
## 保护对象与不可信输入

保护 API Key、上屏/文件隐私、目标设备状态、游戏进度、配置恢复点和会话归属。不可信输入包括模型输出、网页内容、UI 树文本、文件内容、工具结果中的外部字符串、MCP 描述、用户配置端点返回体。

Prompt 不能形成隔离；提示注入可能诱导模型选择工具，硬边界必须由 Native 授权、资源约束和系统权限执行。ADB 调试即使已启用也只允许 Native 已审查命令形式；未知程序、参数与脚本语法都拒绝。不能把 Prompt 或黑名单字符串匹配当作执行隔离。

## 授权交集

允许一次执行必须同时满足：可信本地桥、活跃 Run、当前 Session 能力、工具在有效集合、参数合法、系统权限/后端就绪、资源范围正确、epoch 当前、未超时。UI、Runtime 和 Native 都可以早拒绝，最终决定只属于 Native。

操作输入 executor 与设备命令 executor 分开；即使二者共用 Shizuku 服务，也不能让 screen_control 的 JS 入口传命令字符串。系统授权只是通道，不代表所有 Session 自动获得全部能力。

已有 Shizuku shell UID 2000 授权时，Native 会自动绑定 UserService 并启用本应用固定的无障碍组件；已启用但未连接时可只重连自身组件。此设置操作不进入模型工具集合，不接收任意组件或命令，不打开会话的 screen_control / adb_debug 开关，也不会自动请求尚未授予的 Shizuku 权限。读、合并和读回检查保留其他已观察到的服务；系统设置 API 没有跨进程原子合并保证。未授权或后端不可用时提供手动入口。

截图是新的只读观察：只能沿用已授权且仍相同的显示/角色，实际拍摄创建新目标 ID，回调及返回前验证该新目标；下一轮模型请求才采用该 ID。输入不会因为新观察自动更换旧参数的资源身份，旧 frame/10 秒期限不能复活。仅在唯一全屏应用根视图和矩形可触摸区域证据完整时分离布局与触摸区域；最终触摸路径必须同时处于观察/当前区域交集，其他窗口/布局/焦点/包名变化仍拒绝。完整实测及资格限制见 [实机报告](physical-test-report.md)。

## 调试边界声明

Native 与实际 shell UID 2000 执行端共同执行固定的白/灰/黑名单（ShellCommandPolicy）。白名单包括公开状态读取和用户明确指定无需确认的限定亮度、风扇 1/4/5、60/120 Hz、超时及旋转设置；灰名单包括敏感诊断/应用列表读取、焦点与按键分配变更，必须逐条 UI 确认。黑名单包含抹除、格式化、刷机、分区、提权、关闭散热、应用清除/卸载、权限与连接配置，以及未知命令/参数。黑名单不可确认放行。

命令只解析为单个 argv，规范化到审核的 /system/bin 可执行文件；生产路径不调用 sh -c，不支持变量、命令替换、转义、组合、管道、重定向、解释器或第三方二进制。灰名单批准绑定 Native run/request、原始参数指纹、deadline 与 capability epoch；拒绝、停止或重新授权不会复活旧请求。UID 端仍重新分类，即使伪造 approvalHash 也不能运行黑名单命令。debug.command_policy 只读分类，不执行。

Thor 双屏亮度使用固定的 debug.thor_brightness 工具：参数只接受 read/set、upper/lower、0–255；由 Native 识别当前显示编号并通过已审查固件接口执行。read/set 均为白名单，但实际 set 仍在授权 commit 内提交。未知固件/缺失屏幕拒绝，不开放任意 Binder transaction。服务在验证 app caller、owner、短 lease 后只为此固定操作使用 shell 自身身份，取消/超时仍生效。

不把限制后的命令接口宣称为通用 Shell 沙箱，也不将它用于绕过其他工具授权。命令能力和所有文件工具仍依赖当前会话 adb_debug；系统设置不能由 JS 自行授权。停止不能撤回已提交的系统变更，恢复需要新的合法操作。结构化文件工具的备份保护仍只覆盖其受管配置目录。

## WebView 与桥

只加载 APK 内可信资源，经固定本地 HTTPS origin 提供；message listener 使用精确 allowedOriginRules，校验 main frame 与连接身份，不使用 `*`。远程内容不在有桥的 WebView 中导航/渲染 iframe；外链交给无桥浏览器。

Markdown 禁止执行 HTML/script/javascript URL，远程图片默认不自动加载，避免隐式网络泄露。禁用不需要的 file/content 访问和生产调试开关，CSP 按实际依赖最小配置，不能为兼容性无条件放开远程脚本。

参考 [Android Native bridge 风险](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges)。本地可信页面遭 XSS 仍可能滥用已授权能力，因此 origin 检查不能替代参数/资源/lease 校验。

## 网络与秘密

模型和搜索凭据分别绑定端点；桥不向 JS 返回明文；通用 header 替换方案由 POC-04 验证。模型请求只能访问已配置目的地和允许的方法/路径；用户要求网络自由访问：HTTP/HTTPS、内网、回环及代理 fake-IP DNS 均按系统网络实际可达性连接，使用系统 DNS 与代理，不做地址段屏蔽。重定向仍不跨目标携带凭据。

诊断、错误信息、HTTP header、命令输出可包含秘密，保存/显示前脱敏并限长；不能承诺自动识别所有敏感配置，导出前由用户查看范围。模型本身可以看到被授权工具返回的数据，应用不能撤回已经发送给用户服务的内容。

## 主要威胁与测试

| 威胁 | 控制 | 验证 |
|---|---|---|
| 网页让模型调用已关闭工具 | 不注入＋Native 实时校验 | 伪造工具、旧 epoch、直接 bridge 调用 |
| A 会话请求借 B 权限执行 | Native Run/Session 绑定，不信任 JS 自报 | 交叉 ID 和切会话竞态 |
| 恶意网页/iframe 调 Shell | 精确 origin/main frame、无远程导航 | 跨源、同源子 frame、重定向 |
| API Key 传给另一个站点 | origin/path 绑定、拒绝凭据重定向 | 302 到恶意 host、日志脱敏 |
| 配置路径换成符号链接 | 规范化＋操作时重新验证＋hash/CAS | TOCTOU、文件替换、SAF grant 撤销 |
| 手柄卡住/目标切换 | 资源租约、目标校验、受限释放 | 断服务、停止、旋转、焦点改变 |
| 模型无限工具循环 | 请求轮次/输出预算、用户停止；普通任务无时间上限 | 无进展循环、超大结果 |
| 压缩复活旧授权或秘密 | 来源标签、有效工具覆盖、投影测试 | 关闭后摘要/旧系统段重新出现 |

## 首版明确不提供

对恶意/被攻破 OS 的完整防护；任意 Shell 的强沙箱；已经上传数据的远端删除保证；所有 side effect 的事务回滚；Root/ROM 级安全承诺。独立 APK 和不上 Play 只改变分发方式，不消除平台权限及应用自身安全责任。

## 测试 APK 的独立边界

Thor Input Lab 不持有 Agent 凭据、Shell 或注入权限，只观察本应用收到的事件。其测试控制协议限制到受信 runner，显式组件、签名权限与短 lease；不进入 Agent Tool Registry，不提供写 pass/改原始证据接口。生产包不开放测试控制入口。调试 Shell 能力很强，受控测试必须排除篡改 Lab 报告；此设计不宣称对恶意 shell/系统具备防作弊能力。详见 [测试 APK](input-lab.md)。
