## 产品行为

- 设置 → 模型服务可保存多套配置，包括同一 Provider 的多个账号。每套配置分别保存名称、服务类型、地址、模型偏好、参数和加密 API Key。
- 一次只选择一个当前 Provider；发送框仅展示当前 Provider 的模型。点击“使用此服务”直接切换，不要求重新填写 Key，不重建运行环境。
- 每个会话一次使用一个模型。切换当前 Provider 影响之后启动的任务；已开始的任务继续使用启动时的配置和凭据。允许不同会话的既有任务继续并行。
- 编辑已有服务时，Key 输入框保持空白，留空保存会保留该服务自己的 Key。修改自定义服务地址需要重新指定凭据；其他服务的 Key 不参与保存或连接测试。
- 旧单服务配置和 Key 自动迁移；原偏好和原凭据条目保留。自定义模型的连接探测按配置 ID、配置版本、模型和协议隔离。
- 测试设备新增了 DeepSeek 官方配置，使用官方模型 `deepseek-flash`。验收后保留该配置，并恢复原先选中的 Provider。

## 内存与磁盘

启动只读取话题元数据和当前选中项，不加载历史消息、已结束运行、完整事件流或图片正文。若存在未结束的运行，只读取这些运行并记录为中断，不重放操作。

Native 常驻的正文和事件只属于活动任务。启动新任务时，临时读取同一会话的持久化 Pi turn 和必要的旧失败记录；完整 turn 不重复读取流式事件，历史图片按实际引用单条读取。任务完成后释放运行、消息、事件以及相关索引。未加载的数据不会因局部保存被删除，删除历史必须明确指定会话 ID 并执行数据库级联事务。

运行层不再永久缓存所有会话的 Pi Agent。一次任务内的模型与工具循环继续复用 Pi Agent；结束、失败或取消后释放。下一次追问使用相同会话 ID，从持久化上下文重建，保留已确认的工具结果，避免重放副作用。诊断中的 `historyRestored` 表示恢复了历史，`piSessionReused=false` 表示没有保留上一轮空闲 Agent 实例。

历史页面只保留显示需要的窗口：默认最近 12 轮，点击“加载更早消息”扩展；事件投影有数量上限。SQL 在进入页面前裁掉完整 Pi turn、上下文清单和图片正文。话题标题等少量元数据、当前页面的展示数据仍按界面需要保留。语音上下文读取最近消息和必要来源标记，不加载整段会话。

关闭运行环境时也释放历史索引、页面状态及待发送通知。通知采用单槽合并，避免主线程排队的闭包分别持有大量旧页面快照。

## 验证与证据

真机验收基于原有 189 个会话、200 次运行、400 条消息、63,499 条事件和 249 个附件，未清空数据库。

- Go → DeepSeek 官方 → Go 的真实五轮验收覆盖同一会话追问和两个任务并行，所有请求 HTTP 200，测试口令匹配。
- 切换 Provider 后，已启动的 Go 任务仍继续运行，新任务使用 DeepSeek；两个生成区间有重叠且输出不串用。
- 启动和每轮任务结束后，Native 的运行、消息、事件和附件驻留数均为零；运行层的活动执行、驻留会话和挂起 RPC 数均为零。
- 新增 Provider 及其 Key 保留；测试会话已删除，原有历史、配置和原凭据条目逐项完整性核对通过。
- 真机设置页通过实际按钮反复切换服务，验证 Key 状态保持、模型列表只有当前服务、Host 与两个 WebView 未重建。
- 模拟器覆盖空配置启动、按需读取、3 MiB 历史、部分保存、失败回滚、跨会话隔离及旧存储兼容性。

首次验收在旧的全量加载实现中复现了 256 MiB Java 堆内存不足；该失败日志保留在证据目录。之后的验收使用上述按需存储实现。

安全报告与执行日志位于 [tests/provider-multi-config-evidence](../tests/provider-multi-config-evidence)。报告只记录计数、模型名称、HTTP 状态和合成测试标记是否匹配，不记录 Key 或用户对话正文。私有数据库备份和凭据文件没有加入版本库。
