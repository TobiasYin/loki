# UI / UX 设计

## 0.8 交互实现与实际复验（2026-10-17）

本节记录当前实现；后文保留早期设计讨论，涉及更新时间常驻、原生模型选择框、默认展开工具卡等描述，以本节为准。

聊天保留安全 Markdown、流式正文与紧凑扫光状态。普通输入等待／提交不显示“未校验动作”或“副作用未知”；明确未知结果与异常结束仍显示需要处理的摘要。模型和思考强度使用自定义可访问列表，支持实际键盘方向键、Enter、Escape；会话标题保留全文，由可用宽度决定省略。能力开关即时反馈，匹配确认或失败后提交／回滚，旧快照与旧请求失败不会覆盖更新选择。

页面变化作为正常的继续分支处理：保留当前任务，重新读屏后再判断下一步，页面变化及重新观察状态仅显示在对应操作工具卡片中，不显示全局提醒；不自动重放旧点击或把未知提交说成未执行。该修复目前通过源码测试，尚待对应安装包的设备验收，具体行为与验证范围见 [页面变化后继续任务](target-change-recovery.md)。

工具历史默认折叠时不构建卡片；展开外层才创建摘要，展开单卡才解析、渲染输入和结果。思考和工具使用原生 details 语义，移除按钮悬停底色并保留键盘焦点提示。展开收起采用 250ms、`cubic-bezier(.4,0,.2,1)` 的高度过渡；快速反转从当前高度开始，流式更新续接动画，收起结束才释放内容。系统减少动画时直接完成，不保留折叠内容。

后台执行由 Service 持有同一个引擎、WebView 和 Host；Activity 异步绑定后才取得页面。设置保存只在空闲时通过 Service 所属入口关闭旧 Host、加载新配置，保留单一写入者。模拟器测试也等待实际绑定与页面就绪；合成 UI 拦截在测试后通过空闲重载清理，不依赖 finish 销毁共享文档。

实际复验使用同一 App SHA-256 `9c03e723c21978c809480b5fc75e717ca248f845ee91b2888f872be64373fee8`。provider 两项、临时 SQLite 两项、launcher 三项使用测试包 `906a0eec…`；正常与减少动画两项使用后续测试包 `3cac861a…`。九项均通过，但不是同一个测试 APK 一次完成。正常动画六组分别有 8、3、8、10、9、20 个真实中间高度帧，均采到 settled；部分帧间隔超过 200ms，不声称稳定 60 FPS。减少动画在新进程前应用真实系统偏好，没有替换 matchMedia。

随后在 **256 集成验证时点**，App `256498c4…` 与测试包 `d0866d32…` 又实际完成同包十四项（上述九项加选择器状态三项、后台两项）。正常 UI 21.048 秒、减少动画 8.413 秒；正常六组中间帧 11、7、7、10、9、30，全部 settled、无超时；最大帧间隔 83.4ms。这份同包结果不转用于之后的 Runtime 动作后置观测修复包；旧 `9c03…` 成功记录仍保留原归因。

之前固定采样窗口曾在真实动画未结束时停止，保留了失败报告。现在采样在实际输入后至少 550ms、且 WAAPI 与页面状态均结束后停止，硬上限五秒；至少两个中间帧的标准不变。完整包身份、成功日志、失败轮次说明和非敏感截图见 [0.8 模拟器证据](../tests/release-0.8-evidence/emulator/README.md)。这些是实际 WebView 与平台组件验证，provider 使用受控本地 SSE，launcher 拦截 Intent；不替代真实云端、Thor 游戏任务或双屏控制验收。

## 页面结构

单主聊天页面，左侧抽屉切 Session，设置作为次级页面。不用 Dashboard、多标签页或常驻工具控制台。下屏实际尺寸、density、系统栏与键盘占用由 POC-01 确认，不把营销物理尺寸换算成固定 dp。

```text
┌──────────────────────────────┐
│ ☰    当前会话标题        ＋ ⋯ │
│                              │
│ 用户：这个设置有什么作用？   │
│                              │
│ 正在查看上屏                 │
│   应用信息     已完成         │
│   读取界面     执行中         │
│                              │
│ Assistant 回答逐步出现        │
│                              │
├──────────────────────────────┤
│ 输入问题…                    │
│ [能力 · 2 项 ⌄]       [发送] │
└──────────────────────────────┘
```

完成后执行轨迹收为一个紧凑入口“已完成 · 2 项操作 ▸”，聊天主要显示 User Message 和 Assistant Message；点入口可展开工具列表与有界详情。折叠不隐藏错误摘要、等待确认或“停止未完全确认”等仍需处理状态。

## 侧拉 Session

显示新建、最近会话列表、标题、更新时间、当前活动标记和设置入口。支持重命名、归档和删除；删除前显示影响范围，活动 Run 需先停止。首版不做文件夹/标签/云同步。标题可由首条用户文本生成，不因命名额外发送一次模型请求。

切会话不改变其他 Session 能力；活动 Run 标记一直可见，防用户误以为切页就停止。无会话时空态展示一句用途说明和输入框，不默认抓屏构造欢迎内容。

## 四能力多选下拉

放在参考图“深度思考”所在的输入区位置；本项目此控件只管理能力，不混用推理强度。

| 行 | 初始勾选 | 辅助状态示例 |
|---|---|---|
| 上屏感知 | 是 | 已就绪 / 需开启无障碍 |
| 联网搜索 | 是 | 已就绪 / 未配置搜索服务 |
| 屏幕操作 | 否 | 触摸可用，手柄待验证 / 需 Shizuku |
| ADB 调试 | 否 | Shell 与文件访问；高权限 |

点击后即保存到当前 Session。开关必须区分“已选择”和“有效工具已可用”；不要用灰色勾选让用户猜测。权限不足时保留选择并提供明确设置路径，不自动跳多个系统授权页。

运行中关闭能力立即更新、取消相关执行并显示简短状态；关闭后再开启只授权未来调用。开启操作/调试时展示边界说明；不会把新开关应用到其他会话。

调试说明文案：**“开启后，Agent 可运行设备 Shell 并访问系统允许的文件。Shell 可能截图、操作屏幕或联网，因此其他能力开关无法限制 Shell 的这些行为。部分应用私有文件仍可能无法访问。”**

## 聊天与运行状态

| 状态 | 用户看到的内容 | 可操作 |
|---|---|---|
| 未配置模型 | 普通空态＋“配置模型服务” | 设置；不自动请求 |
| preparing | 正在准备，显示缺失权限/服务时的准确原因 | 停止 |
| generating | Assistant 文本增量；不显示伪造的思维链 | 停止 |
| executing_tools | 默认展开名称、目标、耗时、进度/结果摘要 | 停止、关闭能力、展开详情 |
| awaiting_user | 具体文件差异/命令/风险与批准对象 | 批准或取消；普通读工具无此步骤 |
| completed | 最终回答＋自动折叠的执行入口 | 手动展开、复制回答 |
| failed/cancelled/interrupted | 简短原因＋已完成和未知的副作用 | 展开、发起新 Run；不一键盲重放 |

工具卡片使用“查看应用版本”“读取上屏界面”“修改配置”等用户语言；技术 ID、原始参数和脱敏日志放二级详情。输入事件“已提交”与“效果已确认”不同；模型无法观察时不显示成功改变游戏的勾选结论。

## 输入与焦点

发送后按钮变停止；无剩余输出时也保留停止当前设备动作的入口。键盘弹出时保持输入框可见，聊天区域可滚动，不能遮住危险确认和取消。不要为了改善游戏焦点把整个聊天窗口设为不可聚焦而导致无法输入。

在 Thor 下屏操作是否使上屏暂停、改变物理手柄路由需 POC-01/07。焦点恢复若有副作用需明确触发，不通过隐藏点击抢回游戏。首版不承诺一边下屏键盘打字一边完全无干扰地向游戏输入。

## 视觉与可访问性

使用中性背景、单一强调色、轻分隔、紧凑但足够触控面积的控件。初值正文 14–16sp 等效、主要点击目标约 48dp 等效；这些是设计起点，实际 WebView CSS 密度/字体缩放需真机校准。支持浅/深色和系统字体缩放，状态不能只靠颜色表达。

列表、Markdown、代码块和长 URL 必须不撑破下屏；图片缩略图按需加载。远程 HTML 不进入有桥页面。历史手动展开保持到用户收起，新的 Run 完成只自动折叠自己的执行区。

## UI 验收

### 2026-10-18：仅保留最新一条阶段消息

同一轮执行在折叠状态下只显示最新一条 Assistant 文字消息，较早的阶段汇报随执行过程折叠。运行中仍显示最近两项思考或工具活动；继续思考或调用工具不会提前隐藏最近的文字，只有开始输出下一条文字时才收起上一条。任务完成、失败、取消或中断后保留最近一条文字，过程默认收起。

展开执行过程后，所有已加载的文字、思考、工具和上下文整理事件按原始时序混排；复用同一组节点，避免重复消息。手动展开状态在流式刷新时保留；本轮终止时重新默认折叠。该改动只调整展示可见性，不修改 Pi 会话、上下文或磁盘历史。事件窗口不完整时仍保留完整的已保存回复，避免拿残缺增量替换完整消息。

验证：130 项 Web 测试通过，620×540、360×640 和 620×180 三种浏览器布局通过时序、流式推进、展开收起动画和防重复检查，Debug APK 与 lint 构建通过。合成界面截图与报告位于 `build/activity-collapse/latest-reply-*.png`、`build/activity-collapse/browser-check.json`。本轮 ADB 未检测到 Thor，未执行真机安装。

POC-10 检查空态、长回答、长工具结果、30 项工具事件、错误、停止、能力不可用、50 个会话、200 条历史消息、键盘、旋转、深浅色与字体放大。四图补齐后只做视觉对照，不倒推未观察到的产品行为。
