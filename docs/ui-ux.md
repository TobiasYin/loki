# UI / UX 设计

## 参考资料的边界

原对话提到四张参考图，但本次 read_thread 仅返回文字和“附图未包含”的标记，无法实际观察图片。以下忠实采用用户已说明的极简风、侧拉列表、主聊天、工具状态和底部多选下拉；字体、间距、图标、颜色不能声称与四图逐像素一致。补图后的视觉核对为 Q-09，不阻碍当前结构设计。

## 页面结构

单主聊天页面，左侧抽屉切 Session，设置作为次级页面。不用 Dashboard、多标签页或常驻工具控制台。下屏实际尺寸、density、系统栏与键盘占用由 POC-01 确认，不把营销物理尺寸换算成固定 dp。

```text
┌──────────────────────────────┐
│ ☰    当前会话标题        ＋ ⋯ │
│                              │
│ 用户：这个设置有什么作用？   │
│                              │
│ 正在查看上屏                 │
│   应用信息     已完成         │
│   读取界面     执行中         │
│                              │
│ Assistant 回答逐步出现        │
│                              │
├──────────────────────────────┤
│ 输入问题…                    │
│ [能力 · 2 项 ⌄]       [发送] │
└──────────────────────────────┘
```

完成后执行轨迹收为一个紧凑入口“已完成 · 2 项操作 ▸”，聊天主要显示 User Message 和 Assistant Message；点入口可展开工具列表与有界详情。折叠不隐藏错误摘要、等待确认或“停止未完全确认”等仍需处理状态。

## 侧拉 Session

显示新建、最近会话列表、标题、更新时间、当前活动标记和设置入口。支持重命名、归档和删除；删除前显示影响范围，活动 Run 需先停止。首版不做文件夹/标签/云同步。标题可由首条用户文本生成，不因命名额外发送一次模型请求。

切会话不改变其他 Session 能力；活动 Run 标记一直可见，防用户误以为切页就停止。无会话时空态展示一句用途说明和输入框，不默认抓屏构造欢迎内容。

## 四能力多选下拉

放在参考图“深度思考”所在的输入区位置；本项目此控件只管理能力，不混用推理强度。

| 行 | 初始勾选 | 辅助状态示例 |
|---|---|---|
| 上屏感知 | 是 | 已就绪 / 需开启无障碍 |
| 联网搜索 | 是 | 已就绪 / 未配置搜索服务 |
| 屏幕操作 | 否 | 触摸可用，手柄待验证 / 需 Shizuku |
| ADB 调试 | 否 | Shell 与文件访问；高权限 |

点击后即保存到当前 Session。开关必须区分“已选择”和“有效工具已可用”；不要用灰色勾选让用户猜测。权限不足时保留选择并提供明确设置路径，不自动跳多个系统授权页。

运行中关闭能力立即更新、取消相关执行并显示简短状态；关闭后再开启只授权未来调用。开启操作/调试时展示边界说明；不会把新开关应用到其他会话。

调试说明文案：**“开启后，Agent 可运行设备 Shell 并访问系统允许的文件。Shell 可能截图、操作屏幕或联网，因此其他能力开关无法限制 Shell 的这些行为。部分应用私有文件仍可能无法访问。”**

## 聊天与运行状态

| 状态 | 用户看到的内容 | 可操作 |
|---|---|---|
| 未配置模型 | 普通空态＋“配置模型服务” | 设置；不自动请求 |
| preparing | 正在准备，显示缺失权限/服务时的准确原因 | 停止 |
| generating | Assistant 文本增量；不显示伪造的思维链 | 停止 |
| executing_tools | 默认展开名称、目标、耗时、进度/结果摘要 | 停止、关闭能力、展开详情 |
| awaiting_user | 具体文件差异/命令/风险与批准对象 | 批准或取消；普通读工具无此步骤 |
| completed | 最终回答＋自动折叠的执行入口 | 手动展开、复制回答 |
| failed/cancelled/interrupted | 简短原因＋已完成和未知的副作用 | 展开、发起新 Run；不一键盲重放 |

工具卡片使用“查看应用版本”“读取上屏界面”“修改配置”等用户语言；技术 ID、原始参数和脱敏日志放二级详情。输入事件“已提交”与“效果已确认”不同；模型无法观察时不显示成功改变游戏的勾选结论。

## 输入与焦点

发送后按钮变停止；无剩余输出时也保留停止当前设备动作的入口。键盘弹出时保持输入框可见，聊天区域可滚动，不能遮住危险确认和取消。不要为了改善游戏焦点把整个聊天窗口设为不可聚焦而导致无法输入。

在 Thor 下屏操作是否使上屏暂停、改变物理手柄路由需 POC-01/07。焦点恢复若有副作用需明确触发，不通过隐藏点击抢回游戏。首版不承诺一边下屏键盘打字一边完全无干扰地向游戏输入。

## 视觉与可访问性

使用中性背景、单一强调色、轻分隔、紧凑但足够触控面积的控件。初值正文 14–16sp 等效、主要点击目标约 48dp 等效；这些是设计起点，实际 WebView CSS 密度/字体缩放需真机校准。支持浅/深色和系统字体缩放，状态不能只靠颜色表达。

列表、Markdown、代码块和长 URL 必须不撑破下屏；图片缩略图按需加载。远程 HTML 不进入有桥页面。历史手动展开保持到用户收起，新的 Run 完成只自动折叠自己的执行区。

## UI 验收

POC-10 检查空态、长回答、长工具结果、30 项工具事件、错误、停止、能力不可用、50 个会话、200 条历史消息、键盘、旋转、深浅色与字体放大。四图补齐后只做视觉对照，不倒推未观察到的产品行为。
