# Application Presentation windows

Android 13 can report a real secondary-display `WindowManager.LayoutParams.TYPE_PRESENTATION` (2037) as Accessibility type `-1`. This follows the framework's [Accessibility window-type conversion](https://android.googlesource.com/platform/frameworks/base/+/android-13.0.0_r1/services/accessibility/java/com/android/server/accessibility/AccessibilityWindowManager.java), which does not map Presentation. A readable root alone does not prove that an unknown window is an application Presentation.

The adapter keeps the raw Accessibility type. A separate `PresentationWindowProof` is accepted only after the shell UID 2000 service joins one Accessibility window ID to its server-side `WindowInfo.token`, and that token to the WindowManager `mClient`. The [WindowState implementation](https://android.googlesource.com/platform/frameworks/base/+/android-13.0.0_r1/services/core/java/com/android/server/wm/WindowState.java) supplies that token from `mClient.asBinder()`. The join compares two dumps produced by the same system_server; it does not compare BinderProxy hashes from separate client processes, infer ownership from a title, or match only by package and rectangle.

The dedicated read-only IPC runs fixed `dumpsys accessibility`, `dumpsys window windows`, and `dumpsys accessibility` again. It accepts only an unchanged, unique ID/token/display/bounds/window-structure record with raw WM type 2037, a corresponding public Presentation WindowToken, explicit visible/on-screen/drawn/frame facts, and complete symbolic flags without `SECURE` or `NOT_TOUCHABLE`. Private Presentation, other unknown types, numeric/unrecognized flag formats, truncated output and ambiguous metadata are rejected. Each process has a 2.5-second kill deadline and a 1 MiB output limit. Only qualified metadata for requested calibrated displays/window IDs leaves the service; no raw dumps, window titles, UI text or unrelated package lists cross this IPC.

The service verifies the WM package against PackageManager's real UID and excludes another user, the assistant's UID/package, system UIDs and system applications. A shared UID is not rejected solely for being shared. Each actual Accessibility read must still report the exact qualified package at its root. Existing single-window, visibility, node identity, clipping, overlay, password and lower-screen screenshot security checks remain active. Physical controller focus and Android navigation focus checks retain their separate requirements; this change does not claim to route physical input by display.

Proofs have an absolute five-second lifetime. A hit never extends expiry. Structural events, display identity changes, service/disconnection changes and a changed current window fingerprint invalidate them. In-flight work carries its original generation, fingerprint and inspection start time and cannot repopulate an invalidated generation. Stable layout identity includes real window/token/type/owner/flags/frame facts, never a cache timestamp or random query identifier.

`ThorAccessibilityService.target()` only reads the cache and never starts or waits for metadata I/O. Explicit observation preflight runs before commit/resource locks: ProductHost prepares its two calibrated roles; Gateway validates authorization before invoking the backend's read-only preflight. The backend requests only its calibrated source and, for select/companion reads, the calibrated destination. Off-main waiting is limited to 1.5 seconds with cancellation polling; the bounded read-only worker may finish warming the cache afterward. Main-thread callers never wait. An unavailable or expired proof fails closed and requires another observation.

The Shizuku UserService version is 14. The metadata operation does not open or retire an input lease and does not hold the service monitor, so inspecting a Presentation cannot cancel a bounded held input or delay its cleanup through that monitor.

Core regressions cover the real Android 13 record shape using synthetic package data, exact token joins, unknown-root-only rejection, disallowed raw types, duplicate/mismatched records, secure/touch/visibility/geometry failures, UID/user/system policy, clipping and overlays, stable identity, content/structure revisions, absolute cache freshness/generation and cancellation before Native execution. The first unified core run passed all 13 new Presentation regressions (zero failures/errors/skips, XML timestamp 2026-10-16T18:02:42Z). The unified Android compilation, JVM checks, debug/release builds and lint passed separately. The focused emulator acceptance below uses a real foreign-package Presentation receiver; prior VirtualDisplay Activity tests alone did not exercise the unknown Presentation adapter. The original Citra dumps remain diagnostic evidence, separate from this component acceptance.

It requires the production Shizuku shell service to be running and granted before the case; no metadata injection fallback exists. This is evidence for that run's absolute-TTL boundary, not a retroactive explanation of prior failures without such diagnostics.

Read-only preflight now checks remaining lifetime without renewing or removing the existing proof. When fewer than2000ms remain, it schedules a complete new accessibility–WindowManager–accessibility metadata read and package-owner verification through the existing fixed Shizuku backend. The prior proof remains usable only until its original deadline. A new proof replaces it only after the full reader result, unchanged window key and generation checks pass; its absolute5s lifetime starts before the new metadata read. Failed/late/inconsistent refreshes never extend or resurrect the old proof. Existing1500ms cancellable worker waiting, cache-only target/commit/main paths, owner/secure/clip guards and bounded cache remain unchanged. Inputs are never automatically replayed.

The2000ms threshold is a refresh scheduling reserve, not a guarantee that every tool finishes before expiry. A sufficiently slow tool or failed refresh can still be rejected safely.
