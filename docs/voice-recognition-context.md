# 语音识别动态上下文

火山 ASR 使用 `bigmodel_async`，保留 `enable_nonstream=true` 的流式与二遍识别。每次按住说话，客户端在 WebSocket 首个配置帧中，将当前场景与最近对话通过 `request.corpus.context` 传入。该字段是序列化 JSON 字符串，内部包含 `context_type=dialog_ctx`、从新到旧的 `context_data` 和少量 `hotwords`。

## 数据来源

- 当前选中会话最近最多 6 条有效用户/助手正文，约 3 轮。按新到旧取材，正文预算可能使实际数量减少。工具参数、工具结果、思考事件、流式未完成消息、附件和其他会话均不读取。
- 开启该会话屏幕感知时，复用上屏应用元数据读取器获取已校准上屏的应用名、包名；可选读取唯一已验证应用窗口的标题。窗口标题可能包含运行游戏名，但不会将模拟器名当成游戏名，也不会从旧消息推断“当前游戏”。最近对话中明确提及的游戏仍作为对话语境传入。
- 热词优先使用实际窗口标题、应用名。没有可靠名称时只传最近对话；不为了补充提示进行截图、递归读取组件树、硬件探测或模型调用。不加载 Skill 正文。

## 边界与生命周期

`ProductHost.requestVoiceRecognitionContext` 在状态所有者队列中构建每次录音的独立快照，检查所选会话、归档状态和活动任务，并在设备读取前后检查感知授权。关闭感知后，当前应用信息和已标记为屏幕来源的助手正文不会传入。已知保存凭据所在消息，以及匹配明显凭据标记的内容被排除。

录音线程先启动，动态上下文 Provider 在 WebSocket 建立后、首帧发送前运行。聊天入口最多等 250 ms；不可用或超时就使用无上下文请求，超时取消后会跳过后续可选读取。对于需要 Presentation 身份证明的窗口，只在后台刷新已校准上屏的只读窗口证据，最多等 100 ms；现有输入工具的证明等待与校验保持不变。Provider 不持有录音生命周期锁；它返回后再次检查取消/关闭状态，取消后不发送配置或音频。

单条正文最多 240 UTF-8 字节，场景与正文合计最多 1000 字节，热词总计最多 72 字节，序列化 JSON 最多 2048 字节；不会拆开 Emoji。原始超长名称不会被截短后充当热词。这些是保守客户端字节限制，不宣称等同火山 tokenizer 的精确 token 数。

上下文只在当前录音实例与请求内使用，不写入语音状态事件或持久化记录。最终发送文本仍来自 ASR 最终结果，不通过大模型改写。长按、松手提交、取消和无语音的原有行为保留。

## 验证

- 格式与传输单测解压首帧，验证 `corpus.context` 是字符串，包含场景、按新到旧对话和热词；无上下文请求兼容旧格式。
- 有界文本、Emoji、去重、凭据、角色排除、窗口标题、跨录音隔离回归。
- 本地 WebSocket 验证配置先于音频、Provider 异常降级、录音不等待 Provider、等待 Provider 时取消后零帧、松手后最终结果只提交一次。
- `PhysicalVoiceContextTest` 使用两个自有合成会话与已有火山 TTS 固定 PCM，验证真实主机来源隔离、感知开关、上屏信息和真实 ASR；不创建模型 Run，不录制用户麦克风，不发送 Agent 任务。该测试只能证明链路工作，不代表已有识别率提升的对照统计。
