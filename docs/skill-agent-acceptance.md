# Agent 自行创建与复用攻略 Skill 的验收

本轮使用 Android 16 模拟器和真实 OpenCode Go Responses / `deepseek-v4.1-flash`，由 Agent 联网收集资料并调用 `skills_save` 创建 `stardew-valley-guide`。攻略正文不由测试程序预置。Thor 真机测试继续暂停。

## 验收流程

1. 新建空会话，开启联网，只提供主题、适用版本、文件组织和保存要求；不提供攻略答案。Agent 自行读取内置创建指南、查重、Brave 搜索、读取网页并保存。
2. 保存时由 instrumentation 点击真实产品的批准按钮；只接受目标 Skill 的保存请求。报告明确记录自动点击，不声称真人批准。
3. 重新启动宿主，从持久存储读取已保存 Skill。另起空会话，通过输入区 `+` 中的 Skill 选择器勾选它。
4. 在新会话分别提问春季雨天鲶鱼路线、春 19 日补种豆类的期限，以及低等级但已经持有铱金竿/钓具的装备问题。问题不含 Skill 名称和引用文件路径，要求 Agent 自行从已挂载目录匹配、读取正文，再只读取对应专题。
5. 加入无关算术题和未挂载目录题，验证不会读取攻略；检查新会话继承上次 Skill 选择。

复用题暂时关闭该测试会话的联网能力，以验证答案来自保存的资料。这是验收条件，不改变产品的自由网络访问行为。

## 检查依据

- Native 持久化事件、最终完整工具参数、实际发送给模型的 HTTP 请求体共同核对；不把思考中的计划或未保存草稿当作成功。
- 首次请求不能包含任一攻略文件的完整正文。模型调用 `skills_read` 后，后续请求才应包含对应文件内容；参考文件分题加载。
- 新会话上下文不包含创建会话的历史，宿主重建后文件 hash 保持一致。
- 独立核对 [Catfish](https://stardewvalleywiki.com/Catfish)、[Green Bean](https://stardewvalleywiki.com/Green_Bean) 和 [Bundles](https://stardewvalleywiki.com/Bundles) 的地点、时间、生长天数与普通献祭要求。自动断言是基础检查，还需检查完整答案中的条件与行动建议。

这是攻略知识与 Skill 工具链验收，没有启动或操作星露谷游戏。

自动化只检查基础内容和流程，完整答案另做事实复核：第一版回答对地点与时间判断正确，却建议竹鱼竿使用 Trap Bobber，答案质量不合格。随后由 Agent 自己重读当前 Skill、检索并读取六个鱼竿/钓具 Wiki 条目、提交修订，再在同一研究会话中精简购买条件与装备条件。攻略正文与引用文件都由被测 Agent 写入，验收程序没有替它编写游戏规则。作物参考文件在这两次修订中均保持字节不变。

来源核对补充：[Bamboo Pole](https://stardewvalleywiki.com/Bamboo_Pole)、[Trap Bobber](https://stardewvalleywiki.com/Trap_Bobber)、[Iridium Rod](https://stardewvalleywiki.com/Iridium_Rod)、[Tackle](https://stardewvalleywiki.com/Tackle)。购买解锁与持有后的槽位能力分别检查。

## 本轮发现并修复的问题

- 长时间流式生成中，界面积压 `evaluateJavascript` 调用，真实发生 V8 heap OOM。现在等待上一份页面状态完成交付，只保留一份待发最新状态；页面投影聚合同一思考块、正文块和工具参数，Native 原始事件完整保留。
- 网页读取先去除脚本、样式和页面头部，再截取正文；避免脚本噪声占满结果预算。
- 按用户后续要求，普通模型任务不设总时间或生成等待上限；配置探测保持 3 分钟，单个网页/设备工具仍有各自超时。Native 停止、失联和授权撤销仍即时生效。早期三分钟、十分钟失败证据保留。
- 模型在资源映射格式下反复把第二个文件放错层级。保存接口改用 `files: [{path, content}, ...]`，内置指南和错误提示同步更新；Native 兼容旧资源映射调用。严格参数、路径、版本和批准校验继续生效。
- 单个网页超时原先会撤销整个任务的授权，使模型无法换源。现在取消当前工具调用；用户停止、授权撤销和宿主失联仍取消整轮任务。回归覆盖超时后同一任务继续搜索。
- 每个会话复用一个 Pi Agent，追问重新绑定当轮 Native 权限与工具。逐消息保存领域检查点；失败回合也保留已取得的结果，未确认的工具结果明确标为未知，不自动重放。宿主重启后从持久记录恢复上下文，旧版只保存用户问题的失败回合可从 Native 事件恢复观察结果。

早期失败和重试分别保留在忽略的 `build/integration/skill-live-attempt-*` 中，不以最终成功覆盖失败记录。

## 复现入口

真实配置必须已通过 Native 设置写入模拟器，模型与 Brave 密钥只在 Keystore 中保存。不要在同一个安装上运行会覆盖真实配置的 fixture 套件；通用回归使用另一台隔离模拟器。

```sh
ANDROID_HOME="$HOME/Library/Android/sdk" python3 scripts/emulator-live-skill.py \
  --serial emulator-5554 --phase all \
  --output build/integration/skill-live-new-run
```

入口只接受 `emulator-*` 并再次断言 `ro.kernel.qemu=1`。不会清空资料或替 Agent 写攻略。`--phase create` 只创建，`--phase verify` 可复用已有攻略重新运行独立会话验证；输出目录必须是新的。创建和复用分两个 instrumentation 进程，检查跨进程持久化。原始请求证据存于本机忽略目录，不将凭据或完整抓包提交版本库。

可用 `--resume-session <已有失败会话 ID>` 继续真实创建：从该会话原本取得的网页和工具结果继续，测试不注入攻略内容，也不重新研究。报告区分旧研究和本次保存，并核对首次请求包含失败回合的历史。创建后增加一次无工具追问，验证复用同一个 Pi Agent。

`--phase refine` 验证 Agent 根据真实失败反馈自行核查并修订 Skill；`--phase tighten --resume-session <研究会话 ID>` 验证它复用研究上下文进行精简修订。两者均保留来源、当前 hash、真实 UI 保存批准、最终文件 hash 和独立导出。最终复用使用 `--phase verify`，在宿主重建后运行五个独立会话。

运行器在安装前复制并固定本次 APK，记录 APK、源文件和原始证据哈希；不会因为并行构建而把未测试的产物记作已安装版本。没有模型或整轮任务的测试等待上限；仅对“尚未成功提交任何任务”的 UI 启动设置故障判定，避免把测试程序误触停止后的空等待当作模型仍在生成。

## 2026-10-16 的实际结论

能力链路通过，攻略答案准确性未全通过。测试使用真实 OpenCode Go Responses / DeepSeek V4.1 Flash、Brave 与 Wiki，创建/修订使用 minimal，复用题使用 low。最终 Skill 为 `stardew-valley-guide`，3 个文件，hash `ae10191293e4dc6277d77ff2181c94140a4b69098f9de0fba74a62811d73ead0`。

| 用例 | 流程结论 | 内容复核 |
|---|---|---|
| Agent 自行研究、保存、根据反馈修订 | 完成；实际点击保存批准；文件跨宿主持久化 | 正文与资料由被测 Agent 写入 |
| 挂载后无关算术 | 不读取正文/参考文件 | 391 正确 |
| 未挂载目录对照 | 不读取攻略，目录不包含该 Skill | 正确列出三个内置 Skill |
| 春季雨天山湖找鲶鱼、竹竿、2 级 | 自行命中；只读正文和鲶鱼专题 | 地点、6:00–24:00、竹竿槽位、留一条正确；额外建议春季关注 Tiger Trout 错误，装备购买与使用的附加措辞仍不严谨 |
| 春 19 补种 Green Bean | 只读正文和作物专题 | 10 天、春 18 最迟、春 19 来不及正确；额外把旅行商车当成非随机途径，违反题设 |
| 已持有 Iridium Rod / Trap Bobber、2 级 | 只读正文和鲶鱼/装备专题 | 正确回答可以装，购买/制作门槛与已持有后的装备能力分开 |
| 失败后继续与同会话追问 | 真实请求 HTTP 200，保留原资料，同一 Pi Agent 追问成功，无工具重放 | 能说明此前保存的名称和两个专题 |

首次出站请求只有名称与简介；所有实际请求都检查了未读取的参考文件没有进入上下文。每道相关题只读取正文加一份对应专题。新会话历史不包含创建或其他测试会话。作物与装备用例完成后也确认了后续新会话继承 Skill 选择。

自动化流程通过不能代表自然语言事实全部正确。本轮保留了所有完整回答和错误扩展的例子，不把“命中 Skill”当作“正确执行攻略”的充分条件。最终五类新会话结果由第 15、17 轮组成，使用同一 App 和同一不可变 Skill 修订；早期第 15 轮的措辞断言没有识别“装不了”，因此完整 JUnit 套件没有通过，后续改为独立事实复核并完成剩余用例。第 17 轮两项流程套件通过。失败续接/追问的真实验证另见第 11 轮的独立用例与隔离模拟器回归。

软件检查为 77 项 JavaScript、210 项 JVM、Lint、debug/release/test APK 及产物隔离；隔离 AVD 报告 22 项测试，其中 21 项执行通过、1 项因缺 Shizuku 跳过，另 4 项接收端解析检查通过。同一最终 App 的一个真实模型响应至下一次请求间隔约 271 秒，超过旧三分钟时限，任务正常保存并结束。

可读结果、可导入试验包与各请求/文件哈希见 [验收证据](../tests/skill-live-evidence/README.md)。该包保留 Agent 最终写入的原文件，不能解读为整套攻略答案可靠性已验收通过。首次创建应在没有同名 Skill 的测试数据上运行；已有该 Skill 时使用 `verify` 或 `refine`，运行器不会清空资料或静默覆盖同名导入。
