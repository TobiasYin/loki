# 读屏拒绝与页面变化的错误优先级

本节记录独立后续源码修复的历史快照。收集该快照时，本补丁**尚未进入当时执行 game12 的 `429ffa7d…` App**。既有 115 项停止边界快照和 Gradle02／381 项 JVM／429 安装包证据保持原样，不能改记为已包含本修复。

当 Native 已返回 `PERMISSION_MISSING` 或 `SECURE_CONTENT`，且同一时刻页面来源发生变化时，旧代码会先执行纯读结果的来源一致性检查，把安全拒绝误报为 `TARGET_CHANGED`／重新观察。本次以真实 Pi 和三种 provider 协议的受控 SSE 复现该组合；原有安全错误测试只使用输入工具和稳定来源，未覆盖此场景。

修复仅改变读屏错误回执的优先级：先复验当前 Run／Session／Lease、epoch、有效期、用户停止和所需能力；Native 读屏回执已有固定错误时，保留真实错误码，丢弃正文和附件，不因旧来源变化覆盖错误。最小 receipt 与证据引用继续保留，`unknown` 不等于没有执行。Native 真正返回 `TARGET_CHANGED` 时仍进入重新观察。

没有错误的成功读屏结果继续执行原有来源校验、正文／附件处理和处理后的第二次 authority／来源校验。其他工具保持现有结构反馈，例如非读屏 `COMMAND_BLOCKED` 的原因和允许的替代操作不会被这次读屏规则无谓丢弃。

正式新增 24 项回归，每种协议各 8 项：两种真实安全拒绝加来源变化、Native `TARGET_CHANGED`、成功但来源过期、非读屏结构反馈，以及用户停止／epoch 撤销／能力关闭优先。检查包括拒绝附件从未读取、拒绝正文不进入事件／上下文／下一模型请求，真实固定错误进入后续请求，receipt 事实保留且工具不重复执行。

本轮软件结果和冻结源码哈希见 [独立回归补充证据](../tests/release-0.8-evidence/native-read-error-priority/README.md)。这些受控端口测试不代表 Native 实机再次触发了同一问题，也不替代下一安装包的 Gradle、Android 或真机验收；当前真机流程无需为此源码验证而中断。

## 后续真实 Native 空错误码修正

上述139项是当时的受控端口快照，成功端口省略了error字段；不覆盖Android实际成功回执的`error:null`。game13实机暴露该空值被旧判断误作错误，game14则因这次失败写入的空工具正文无法续跑。后续分别增加固定错误码／空值归一，以及只作用于历史工具正文的投影兼容；不会把真实权限、安全或显示器错误改成页面变化。独立213项软件快照见[Native空错误码证据](../tests/release-0.8-evidence/native-null-success/summary.json)，旧快照及对应包身份保持不变。
