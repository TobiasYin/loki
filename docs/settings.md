# 用户设置与配置优先级

> 2026-10-13 状态更新：五模块已开发并进入正式软件整合。本文早期“仅规划/未授权/无 APK”等叙述保留其历史背景；当前实现、实际测试与尚未完成的 Thor 验收，以 [中文集成报告](integration-report.md) 为准。来源模块旧测试不等于本次集成结果。
## 配置层次

全局保存模型/搜索连接资料、外观、数据保留、上屏映射和系统状态。Session 保存四项能力意愿与选定模型配置引用。Run 绑定当时的模型配置 revision，并实时读取能力 epoch。系统授权始终由 Android/Shizuku 决定，不能被数据库中的勾选伪造。

新 Session 固定默认 ON/ON/OFF/OFF；首版不提供改变此默认顺序的全局模板，以免偏离产品需求。会话模型可以选择不同 profile。模型设置修改不热替换进行中的 Run；下一 Run 生效。能力关闭即时生效，不等到下一 Run。

## 设置页

| 区域 | 字段/操作 | 验证与反馈 |
|---|---|---|
| 模型服务 | 显示名、两种协议、基础 URL、模型 ID、API Key、可选 header、上下文/输出预算 | 保存不等于通过；分项测试文本/图像/工具/图像工具回传 |
| 联网搜索 | 后端选择、URL（适用）、key、语言、结果数量 | 无配置显式提示；测试只在用户点击时发出 |
| 设备与权限 | 上下屏校准、无障碍状态、Shizuku 存活/授权/身份、工具支持状态 | 只在用户进入诊断时收集详细设备信息，不自动加入模型 |
| 会话能力 | 当前 Session 四项多选 | 与聊天底部同一状态；修改立即更新 epoch |
| 外观 | 浅色/深色/跟随系统、文字大小 | 键盘与下屏可触控验证 |
| 数据 | 本地占用、截图保留、会话导出/删除、配置备份管理 | 默认导出不含密钥/原始诊断；明确删除边界 |
| 运行限制 | 最大工具轮次、Run 时长、结果上限（高级项） | 有安全下限/上限；不能绕开撤销/后端权限 |
| 关于与诊断 | 应用版本、已验证设备/组件、脱敏报告 | 诊断报告用户主动导出，不自动上传 |

## 首次使用路径

打开下屏应用 → 配置模型 → 用户触发连接能力测试 → 新建默认 Session → 按需引导感知系统授权和搜索后端。未完成感知/搜索配置仍可纯聊天，不能把工具失败伪装成“模型理解不了”。

首次尝试操作/调试时说明所需系统服务与权限，用户选择是否继续；不在首次启动强迫授权所有高权限。用户取消系统授权后保留错误原因和可回到设置的路径。

## 模型切换

协议/端点/模型变化使 probe 失效，必须重测图片和工具。新 Run 重新编译模型投影，不能原样拼接另一个 provider 的内部签名/推理块/消息 id。附件和领域历史仍保留；超出新模型上下文预算时先压缩，无法满足则明确失败。

## 秘密编辑

保存后只显示末尾掩码或“已保存”，不回填真实 key 到 WebView。替换密钥产生新 revision，旧请求可取消或等待结束，但新请求不得使用已撤销 key 引用。删除配置需先处理引用它的活动 Run；仅保留历史标签供审计，不保留可调用秘密。

## 运行初值

每设备一个 Run；每 Run 最多 20 个模型轮次、总时限 10 分钟；触摸/手柄短动作 ≤5 秒；Shell 最大 60 秒；达到上限停在可解释状态。数值仅为保守设计初值，经 PoC 后调整并记录，不能让模型自行延长授权。

## 原生设置与首次启动引导（2026-10-19）

聊天页右上角只显示新建会话按钮。设置入口固定在会话侧栏底部，会话列表单独滚动。设置首页采用随系统明暗模式的原生分组卡片，包含「AI 与输入」「应用与设备」「帮助」；配置子页沿用统一返回、保存与表单样式。系统返回键或返回手势与页面「返回」按钮逐级返回；从子页回到设置首页或上一级列表时保留原有滚动位置。退出设置回到聊天后，再次打开设置从顶部开始。

首次安装启动时显示两步配置引导，可在设置中的「使用引导」重新打开：

1. **连接 AI 服务**：LLM 模型为必选，提供可点击的模型服务配置入口；必须有当前启用、带凭据的模型服务才能继续。语音识别与联网搜索为可选；推荐 DeepSeek 官方 API，配置后模型和搜索自动共享 Key，搜索也支持 Tavily / Brave，均可直接进入配置。由引导进入的配置页返回或保存后回到引导，刷新状态；配置完成表示资料齐全，实际连通性需使用配置页的连接测试确认。
2. **配置操作权限**：基础为开启无障碍服务，按钮直达系统无障碍设置；进阶为 Shizuku 授权与绑定，展示服务可用状态，未安装或未启动时说明处理方式。操作权限可以稍后开启，完成引导后不再自动显示。

通知与麦克风仍可在「应用权限」中按需配置，语音配置页也提供麦克风授权入口。引导不修改会话能力开关；上下屏映射仍在「设备与调试」中配置。

## 聊天背景（2026-10-19）

入口为会话侧栏底部「设置」→「应用与设备」→「聊天背景」。背景配置即时保存，无须重载执行服务。

- 全局背景支持纯色、手动图片和系统壁纸透传。图片经过系统文件选择器导入，最大 24 MB，按最长边约 1600 像素采样并处理照片旋转，复制到应用私有目录；不依赖长期文件授权。
- 「上屏应用专属背景」可选择已安装且有启动入口的应用，支持按应用名称搜索。专属设置包含独立的来源、毛玻璃程度和不透明度；移除后跟随全局。
- 优先级为已识别上屏应用的专属设置 → 全局设置。仅存在专属设置时，在聊天 Activity 可见期间约每 1.2 秒查询已校准上屏的无障碍前台窗口；不可用、不可见或有歧义时使用全局背景。图片和外观配置不进入模型上下文，也不授予设备操作权限。
- 毛玻璃范围 0–30，背景不透明度 0–100%；0% 完全隐藏图片/壁纸，100% 按当前配色叠加层显示全部背景。文字、输入框和菜单保持独立可读。图片模糊兼容 Android 11，解码与模糊计算在后台执行。
- 壁纸透传使用 Android `FLAG_SHOW_WALLPAPER`，可跟随系统当前壁纸及受系统支持的动态壁纸，不读取受限制的壁纸文件。壁纸毛玻璃需要 Android 12 及设备开启窗口模糊；不支持时设置页提示并保留清晰壁纸。多屏壁纸呈现取决于设备系统支持。
- 「查看聊天效果」返回实际聊天页；应用专属背景只在对应上屏应用被识别时显示。更换或移除图片后，只清理没有其他背景配置引用的旧图片。


## 页面配色（2026-10-19）

入口为「设置」→「页面配色」，提供「跟随系统」（默认）、「亮色」、「暗色」。选择保存在设备本地，覆盖聊天页、会话侧栏、菜单与对话框、原生设置和系统栏。手动亮色/暗色优先于系统模式；跟随系统时，系统深浅模式变化会自动更新界面。

亮色使用浅灰白页面、白色表面、深色文字和蓝色强调色；暗色使用深灰页面、灰蓝色表面、浅色文字和浅蓝色强调色。WebView 使用显式配色，关闭自动二次暗化，避免手动亮色被系统暗色覆盖。

图片和系统壁纸共用同一套叠加规则：亮色叠加 22% 页面浅色，暗色叠加 30% 页面深色，保留纹理与颜色细节；消息、顶部和输入框各自使用与主题协调的半透明衬底。用户保存的毛玻璃程度、背景不透明度和各应用专属背景不会因切换配色而改变。壁纸模式把背景不透明度和主题叠加合并为同一个遮罩，视觉效果与图片模式一致。

配色切换会重新创建原生 Activity 以同步系统控件，但保留 Service 中的聊天 WebView、执行 WebView、当前会话和运行状态；不会重新加载执行服务。配色选择页会在切换后恢复。


### 联网搜索配置页（2026-10-19）

先选择搜索服务，再显示该服务的配置。自动选择页明确展示将使用的服务；DeepSeek 展示官方模型 Key 共享状态与模型配置入口；Tavily 只需 API Key；Brave 的自定义地址折叠在高级设置中。连接测试独立展示状态，输入变更后清除旧测试结论。所有编辑和 Key 删除在点击保存后生效，切换服务保留当前页面草稿。

短横屏采用左右两栏，左侧选择服务、右侧配置和测试；竖屏保持单栏。颜色使用统一的浅色/深色主题。Thor 实机 UI 验证必须使用解析后的下屏，不能直接默认启动到主显示器；桌面与通知入口沿用 LauncherActivity 的下屏路由。

### 模型与语音配置页（2026-10-19）

模型服务列表使用卡片展示默认状态、模型与凭据状态。编辑页将服务身份、模型选择、凭据和连接测试分组；预算、图片能力、自定义凭据头、模型资料刷新及已保存 Key 的移除收进高级设置。模型连接测试仍使用草稿，不自动保存。

语音配置按新版 API Key / 旧版 App ID + Access Token 切换可见字段；识别资源显示版本及计费方式，保留原有资源 ID。密钥删除支持保存前撤销。配置检查只检查资料是否齐全，不连接语音服务或录音；保存后在聊天中试用。麦克风权限入口位于检查卡片内；接入端点与隐私说明折叠展示。

两类表单沿用统一主题，在 Thor 下屏短横屏采用左右分栏，竖屏使用单栏。UI 回归通过 DisplayRoles 解析下屏，不写死 display ID，并校验不保存草稿时模型、语音配置与加密凭据保持不变。


### 上屏应用背景管理与 Thor 壁纸修复

「聊天背景」→「上屏应用背景」使用独立二级页面，不再弹出应用选择对话框。页面顶部持续展示当前上屏应用的图标、名称及背景配置状态；未识别时给出映射与无障碍检查提示。列表使用图标和应用名，不显示包名，可按名称搜索，并切换「全部」「已配置」「未配置」筛选。返回列表保留搜索和筛选状态；详情移除专属背景后回到列表并更新状态。当前上屏和已配置但没有启动入口的应用也会加入列表。

Thor 的 Android 13 下屏会在透明窗口里保留原先的不透明启动帧，仅设置 SHOW_WALLPAPER 不足以露出壁纸。宿主现在使用支持透明的窗口，并在壁纸模式下、绘制聊天子视图之前清除旧的窗口缓冲；切回图片或纯色时恢复普通背景绘制。真机验收同时检查合成后的下屏截图和隐藏聊天层后的 PixelCopy 像素 Alpha，避免把窗口标记存在误判为壁纸显示成功。该路径不读取壁纸文件，也不要求新增存储权限。

## Agent 操作展示与自动截图（2026-10-19）

入口为「设置」→「应用与设备」→「Agent 操作展示」。默认开启，在实际操作的目标屏幕上显示半透明圆形虚拟光标：点击显示放大、缩小的按压反馈，长按显示按住与释放回弹，滑动/拖动只显示沿操作路径平滑移动的圆点、结束时轻微弹跳，不绘制轨迹线；语义点击、文本输入和滚动也显示位置及动作名称。光标不可触摸、不抢焦点，仅本服务创建的光标窗口从操作目标识别中排除，其他覆盖窗口仍按原有规则验证。

开关即时保存，关闭后立即移除当前光标，并跳过约 240 毫秒的动作展示等待。自动截图独立于此开关：点击、长按、滑动、拖动、滚动、语义点击、文本输入、按键、导航和启动应用成功提交后，待页面绘制约 180 毫秒，自动附带操作后的截图、新 frameId 和目标快照。截图前移除光标；下一轮直接使用返回图像，无须再次调用 capture_screen；语义 nodeRef 仍需重新读取 ui_tree。

自动截图沿用已发布的屏幕感知权限、选定屏幕、安全内容检查、截图限频和图片大小限制。屏幕感知关闭、安全页面、目标变化或截图失败时，保留操作已提交的结果，通过 postActionScreenshot=false 与 screenshotError 单独说明截图问题，避免重复操作。停止任务、服务中断或解绑时清理光标。

## 无障碍连接检测与恢复（2026-10-19）

无障碍状态以实际连接为准：执行服务存活期间每秒通过 Android 的服务连接读取服务信息，失效后清除本地残留实例并使旧屏幕证据失效。系统设置仍为开启，不代表服务可用。前台的设置首页、应用权限、使用引导和设备页面会自动刷新连接状态。

- 已启动并授权 Shizuku（shell 身份）时，连接失效进入已有的自动恢复流程；保留连接宽限期、重试退避和工具操作互斥，只有真实服务连接恢复后才显示可用。
- 无可用 Shizuku 时，已开启但未连接会显示「连接失效，需重新开启」。前台持续断连三秒后提醒用户前往系统设置，关闭后重新开启 Thor Agent 无障碍服务；同一故障只提醒一次，恢复后可再次提醒。首次未授权时不主动弹出故障提示。
- Crashed 状态会只关闭再重新开启本应用的无障碍组件，并等待系统确认断开后再开启；不影响其他无障碍服务。仅长期保留异常 Binding 时提示重启应用。自动恢复超过 45 秒仍未连接则停止自动重试并提示手动处理，避免一直显示恢复中；设置写入成功不会被当成恢复成功。
- 恢复阶段保存在最多 64 条的本地诊断记录 `files/accessibility-recovery.json` 中。使用屏幕能力的活动运行另存恢复记录，在聊天的任务操作详情中展示；这组记录独立于 Runtime 事件序号，不干扰模型事件持久化。

### 截图回传质量与性能诊断

默认截图（包括操作后自动截图和 companion 截图）采用 JPEG 质量 80、最长边 1280；主动截图仍可指定 quality=30–95。降低压缩质量不改变 frameId 的坐标变换和图片尺寸。硬件缓冲到 Bitmap 的拷贝在独立截图线程执行，避免阻塞主线程动画。

Native 结果的 presentation.screenshotTiming 提供准备、限频等待、系统获取、Bitmap 拷贝、裁剪缩放、JPEG 编码、缓存写入、最终校验和总耗时，以及实际质量、编码次数和图片大小。此诊断字段不加入模型工具正文；不包含外层动作展示、页面等待、附件回传和网络/模型耗时。模拟器测量、同页质量对比和适用边界见 [截图性能验证](../tests/screenshot-performance-evidence/README.md)。


### 卡片透明度与虚拟实时预览

全局背景和每个应用的背景都可独立设置「卡片透明度」：0% 为实心底色，100% 隐藏底色，文字和按钮保持原有不透明度。消息卡片、顶部栏和输入框同步采用此参数，与「背景不透明度」「毛玻璃程度」互不影响。旧配置自动使用 16% 卡片透明度，无须重新配置图片。

「聊天背景」「应用背景」「页面配色」均内置固定的虚拟聊天预览。Thor 横向下屏采用左侧预览、右侧参数独立滚动；窄屏固定预览在顶部，下方参数滚动。预览使用示例消息，拖动时即时展示背景不透明度、卡片透明度和图片毛玻璃变化；系统壁纸通过预览区域透传实际壁纸，仍使用系统允许的窗口毛玻璃。图片解码和模糊在后台进行，单独调透明度不会重复解码。

编辑某个应用时，预览始终展示该应用正在编辑的配置，无须先把它切到上屏；退出预览后聊天恢复当前上屏应用实际生效的背景。预览不创建会话、不发送消息、不使用当前聊天内容。
