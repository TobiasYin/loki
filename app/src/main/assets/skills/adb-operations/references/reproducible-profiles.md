# 保存与复现 Thor 配置

只在用户要求保存/复现配置时建立持久配置。先读取 thor-device.md 中与任务有关的部分，逐项读取真实状态；不要整份读取系统设置或收集无关应用历史。

一份配置应记录：名称、用途、型号、固件、记录日期、每个工具/命令的原值和目标值、单位、回验结果、尚未支持项，以及是否需要恢复。两屏亮度必须分别使用 debug_thor_brightness 读取，保存 0–255 的实际值与 upper/lower 角色，不把 displayId=4 固化到后续设备。

示例“60 Hz 阅读与配置”配置意图：上屏 96/255、下屏 80/255、min/peak 刷新率均 60 Hz、screen_off_timeout=600000。这些只是示例目标，不是推荐覆盖用户当前设置；只有用户选择该配置时才应用。自动亮度、旋转、焦点、手柄、风扇、性能和充电配置不在这个例子里修改。

复现步骤：

1. 对照型号与固件，读取上/下屏当前亮度、需要改的各项当前值。列出将改变的内容和回退值。
2. 检查命令分级，只发起已审核的参数形式。用 debug_thor_brightness 的 upper/lower 分别设置亮度；亮度为白名单，直接执行后回读。
3. 刷新率降到 60：先 min_refresh_rate=60.0，回读，再 peak_refresh_rate=60.0，回读。升到 120 顺序相反。刷新率和屏幕超时均为白名单，无需批准。
4. 回读两屏亮度和各设置，核对目标；用显示信息核对实际刷新模式。系统限制或用户拒绝会导致部分应用，必须报告已成功、被拒绝、失败和尚未执行的具体项。
5. 测试场景恢复所有实际改过的项目，再读回证明恢复。白名单恢复直接执行；仍有灰名单项目时要用户确认，未批准的不能假称完成。

保存为 Skill 时按需读取 skill-creator，通过 skills_save 创建一个名称明确的配置技能，将目标、单位、固件条件、检查与回退步骤放进引用文件。只有元数据进入默认目录，全文仅按需读取。持久保存需要单独页面确认；不要把设备状态快照自动升级为已授权的后续执行计划。

性能和充电等未开放的直接写操作可以记录原始状态和系统页面操作步骤；注明“需要页面核实，不能通过当前命令执行”。导入配置不得要求绕过黑名单、自动确认灰名单、写 sysfs 或修改 ADB/无障碍权限。
