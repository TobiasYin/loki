# 工具记录按需渲染的软件验证

本说明只记录聊天前端的实现与 JSDOM 软件回归，不包含用户私有历史，也不替代 Chrome、Android WebView 或真机上新 UI 的验收。

## 实现行为

- 工具记录默认折叠时，只保留“查看 N 项操作”摘要，不创建工具 card DOM，不解析结果正文，不递归创建结构化字段。
- 展开外层后，仅创建各工具的名称与执行结果摘要；单独展开某个工具，才解析其输入/结果并显示结构化字段。关闭单卡或外层会释放对应内容 DOM，重新展开时按需重建。
- 保留工具与思考展开状态；当前已展开工具随新事件更新。外层选择在 Native 确认之前也保留，任务终态仍遵守 Native 的收起策略。子工具的 toggle 事件不会修改父级展开状态，键盘/程序触发的 toggle 同样会同步。
- 失败摘要、未知副作用提示和批准/拒绝入口始终位于折叠记录之外；活动扫光条保持可见。常用点击、长按、滑动、手柄和释放输入使用中文名称，并识别模型流式事件中的工具别名。
- 亮度结果只有在对象明确标记 `unit=percent` 时，才将其亮度字段显示为百分比。没有结果的旧终态调用不猜单位；当前运行中尚无结果的亮度输入按现行 0–100 整数百分比协议显示。未标单位的历史原始值不会被重新标为百分比，其他工具的同名字段也不受影响。

## 软件回归与边界

执行 `npm --prefix app test`，本轮全部 **44 项测试通过，0 失败、0 跳过**；`git diff --check` 通过。

相关回归使用合成数据：20 个工具记录，每个结果包含 36 个节点及约 30 个字段；验证默认折叠和连续 8 次流式更新的 DOM 创建量保持有界，展开外层后仍无结构化正文，打开单卡才可读取该工具的末尾字段，关闭后释放内容。另覆盖已展开内容刷新、会话切换、Native 确认前的展开选择、子级 toggle 隔离、失败/未知/批准入口，以及历史 raw 42、124 在四种终态下均不误标 `%`，当前运行中无结果的 42 仍显示 `42%`。

上述结果证明 JSDOM 中的 DOM 构建行为及交互回归通过，不证明浏览器实际帧率、设备耗时改善幅度或新的真机 UI 验收通过。运行状态签名仍需线性序列化历史载荷；本次修复针对隐藏工具记录被重复解析和大量创建 DOM 的开销。实际 Chrome/WebView/真机结果由主流程另行记录。
