# 0.5.1 语音长按修复验收

2026-10-16，AYN Thor 真机。0.5.1 已安装，保留模型/语音配置与加密凭据；源码及范围见 [修复记录](../../docs/voice-hold-fix.md)。

修复当前录音被其他触点取消、把捕获丢失误当松手，以及取消入口出现时按住按钮上移的问题。改为跟踪发起录音的触点，并在 document 接收实际抬起/取消；真正的触摸取消、失焦、后台和明确取消仍会停止，不会误发送。

验收包括两种不同证据：

- **触摸故障测试**：平台触摸在下屏持续 5 秒，中途主动释放捕获，随后在按钮外实际抬起。trusted `lostpointercapture` 没有提前结束录音，只有实际 `pointerup` 发出一次完成命令；按钮位置全程稳定。这项测试连接真实麦克风与火山服务，但屏蔽 Agent 提交，避免环境音发起任务。
- **真实声学闭环**：离线生成的火山 TTS 短句 → Thor 扬声器 → 真实麦克风 → 火山流式识别。实际触摸按住 7.5 秒，未松手不发送，松手后识别并提交“请只回复语音测试成功，不要使用任何工具。”，真实模型回复“语音测试成功”。随后取消一轮，没有新增用户消息；21.855 秒通过。

22 项页面回归、43 项 App JVM、Lint、debug/release/test APK、三种视口布局及产物隔离检查通过。页面回归覆盖其他触点取消、捕获 API 不可用/丢失、按钮外抬起、混合键盘触摸、实际取消及失焦。

旧版单点静止/轻微移动的测试也曾通过，没有采集到用户本人那次原始手势。已确认的是可复现的事件处理缺陷和修复后受控故障测试，不能把所有提前结束现象都断言为同一个原因。旧版失败回归及原始报告均保留。

[结构化结果、触摸时序、产物和原始证据哈希](summary.json)。完整日志、固定 APK 和参考语音在本机忽略目录 `build/physical/voice-hold-2026-10-16/`，本目录不存录音、密钥、完整请求或环境音转写。
