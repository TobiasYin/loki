# 截图质量与分段耗时（2026-10-19）

Android 16 / sdk_gphone64_arm64 / emulator-5554，1080×2400 的 Input Lab 离线选择页。输出为 576×1280 JPEG。交替请求 quality=80/60，各 6 次；另有 4 次真实点击/滑动后的默认截图。全部真实调用 Accessibility 截图与生产编码流程，不调用云端模型。

变更：默认 JPEG 质量 80 → 60，最长边维持 1280；调用方可显式指定质量。硬件缓冲到软件 Bitmap 的整帧拷贝由主线程移到进程共享的独立截图线程。计时放在 Native presentation.screenshotTiming，不进入模型工具正文；自动截图保留该诊断字段及原有动作展示字段。超出预算后降质时，准确报告实际编码质量。

| 指标（6 次中位数） | quality=80 | quality=60 |
|---|---:|---:|
| JPEG 大小 | 17,783 B | 14,446 B |
| JPEG 编码 | 9.823 ms | 5.848 ms |

文件缩小 18.8%。本组编码中位数降低约 40.5%；样本少、页面简单，不代表所有页面或实机收益。

质量 60 的独立阶段中位数：

| 阶段 | 耗时 |
|---|---:|
| 系统截图请求至回调到达 | 18.741 ms |
| HardwareBuffer 包装和软件 Bitmap 拷贝 | 23.121 ms |
| 裁剪、缩放 | 3.325 ms |
| JPEG 编码 | 5.848 ms |
| 缓存清理和文件写入 | 0.893 ms |
| 完成快照校验 | 12.537 ms |
| 截图间隔检查与等待 | 218.873 ms |
| 整个 screenshot() | 330.711 ms |

各阶段中位数不能直接相加等同总耗时中位数。高频对比故意触发现有 350 ms 截图间隔保护；不应把总耗时当作截图 API 延迟。4 次操作后截图的 screenshot() 总耗时约 100–229 ms，间隔检查与等待约 1–9 ms（包含授权/目标检查）。以上均不含截图前的动作展示等待和页面绘制等待，也不含附件 Base64、数据库持久化、网络上传或模型图像处理。

截图 API 和整帧拷贝与 JPEG 质量无直接因果关系；两组获取/拷贝的差异包含调度、预热等波动，不宣称降质能提高获取速度。所有样本均验证 copyOnMainThread=false。尚未在 Thor 实机、复杂图片页面或游戏上测试，未测主线程迁移前后的卡顿差异。

`emulator.json` 为 16 个样本的原始分段数据；`quality-60.jpg`、`quality-80.jpg` 为同一页面对比图；`emulator-instrumentation.txt` 为最终设备测试通过记录。验证同时覆盖默认质量、明确指定质量、返回 frameId 的后续滑动、双屏光标、关闭光标和截图权限拒绝。

Debug APK / AndroidTest APK 构建与 device-android lintDebug 通过。
